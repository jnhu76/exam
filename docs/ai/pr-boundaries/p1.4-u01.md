# PR Boundary: P1.4-U01 — UI Design System Baseline & Settings Form Cleanup

## Primary Goal

Extract shared UI constants, unify semantic color tokens, add ErrorBoundary, fix BrandProvider fallback, wire settings form to existing data, remove dead `/exam/settings` link, and consolidate type sources to `@exam/domain` and `@exam/contracts`.

## In Scope

- Shared constants: `STATUS_LABELS`, `STATUS_VARIANT`, `TYPE_LABELS`, `TYPE_VARIANT`, `CONNECTION_STATUS_LABELS` (new file)
- `ExamStatus`/`QuestionType` types imported from `@exam/domain` (single source of truth)
- `SettingsFormValues` = `UpdateBrandingRequest` from `@exam/contracts` (eliminates local DTO)
- Type guards and safe getters for constants
- ErrorBoundary class component wrapping App
- BrandProvider fallback changed to Chinese
- Settings form: accepts `initialValues` via prop, preserves empty strings as `null` on save
- DashboardPage `StatusBadge` uses shared `STATUS_VARIANT`
- Semantic color tokens: `bg-green-500` / `bg-yellow-500` / `bg-red-500` eliminated
- Native `<select>` replaced with shadcn `<Select>` in CandidateFieldsPage
- Dead `/exam/settings` nav link removed from ExamLayout
- All test updates including global stub cleanup

## Out of Scope

- Backend API changes
- Database schema changes
- New business logic or exam engine changes
- New pages or routes
- i18n framework
- BrandProvider OrganizationSettings integration (no frontend hook exists)
