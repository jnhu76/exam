## 4. Call Chain / Data Flow

```text
User visits /admin/settings
  -> SettingsPage loads settings via api.get()
  -> passes settings as initialValues to PlatformSettingsForm
  -> PlatformSettingsForm.useEffect resets form with initialValues
  -> User edits fields, submits
  -> SettingsPage.handleSave maps empty strings to null
  -> api.patch() sends filtered payload
  -> window.dispatchEvent("branding:refresh")
  -> BrandProvider.fetch re-fetches branding from API
```

| Step | Contract to verify | Failure mode |
|---|---|---|
| `api.get` | Returns `SettingsData` shape | Form shows stale or empty data |
| `useEffect` + `reset()` | Re-initializes form on prop change | Form stays empty after load |
| `handleSave` empty→null | Empty string sent as `null` | Backend receives `""` instead of `null` |
| `STATUS_VARIANT[key]` | Returns valid variant or undefined | Unknown status → crash or wrong badge |

## 5. Contract Invariants

- `STATUS_LABELS` / `STATUS_VARIANT` keys are `Record<string, ...>` (not narrowed) for backward compatibility
- `PlatformSettingsForm` accepts optional `initialValues` prop
- `SettingsPage.handleSave` maps `""` → `null` for all fields
- `ErrorBoundary.handleReset` calls only `window.location.reload()` (no `setState`)
- `BrandProvider` fallback is Chinese: "考试平台" / "内部考核与准入控制"
