## 8. 设计决策说明

### 为什么用接口而非泛型工厂？

Job card 要求 "定义 `BaseTenantRepo<Table>` 和 `BasePlatformRepo<Table>` 泛型工厂"。

实际实现为 **泛型接口**（`AsyncTenantRepo<Select, CreateInput, UpdateInput>`）而非 **泛型工厂函数**。

原因：Drizzle ORM 的 `AnySQLiteTable` 和 `PgTable` 无公共基类，泛型工厂在 `isSqlite(db)` 分支中需要将 SQLite Insert 类型强转为 PG Insert 类型，TypeScript 无法通过。接口方式将类型约束推迟到具体 repo 实现时，由实现者提供正确的表引用。

A02 的每个 repo 实现将 `implements AsyncTenantRepo<Select, CreateInput, UpdateInput>` 满足契约。

### 为什么保留 `resolveOrganizationId` 两个版本？

- `resolveOrganizationId` (strict) — SuperAdmin 必须传 `targetOrganizationId`，否则抛异常。用于基础 CRUD。
- `resolveOptionalOrganizationId` (lenient) — 优雅降级到 `organizationId`。用于 `attemptRepo`、`enrollmentRepo` 等已有此行为的自定义查询。

两个策略统一了现有代码中分散的两种 org ID 解析模式。
