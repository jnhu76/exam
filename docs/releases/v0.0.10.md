# Exam v0.0.10

## Why this release exists

`v0.0.10` is a post-`v0.0.9` administration-efficiency and release-engineering
release. Its user-facing core fixes a real data-volume defect: admin list
pages only ever showed the first 20 records, so anything beyond the default
page was unreachable and the counts displayed were misleading. Around that
core it restores list query state across navigation, adds actionable work
queues to the Admin dashboard, and recovers cleanly from stale exam-extend
conflicts.

The release also lands engineering changes that make releases and
deployments more trustworthy: the production deploy payload is restricted to
a declared runtime-artifact allowlist with a CI oracle, workspace package
test resolution no longer measures stale `dist` output, both E2E paths run
in one pinned Playwright image, candidate deadline serialization on a shared
exam row no longer serializes unrelated candidates behind an exclusive lock,
and the runtime moves to the October Node.js security release.

The release is based on the actual ancestry `v0.0.9`
(`0fbad8915053caf98f760dbac3a3b45bab0db231`) → preparation base `master`
(`b9b7fabb2ac693c1995042f036d9842950637f7a`): 130 commits containing 21
merged PRs (#761, #768, #770, #772, #773, #782, #786–#789, #793, #795–#797,
#799, #802–#807). The release-preparation merge adds only the three
release-authority files.

## Problems solved

1. **Admin list records beyond the first page were unreachable (#785).**
   ExamPage, CandidatesPage, CoursePage and ResultsOverviewPage requested
   only the default first page with no pagination UI; totals over 20 records
   were silently clipped and summary copy was misleading. PR #786 moves all
   four lists to real server-side pagination and adds server-side search and
   status filters: `GET /api/candidates` gains an optional case-insensitive
   `search` over user name/username, `GET /api/exams` gains an optional
   validated `statuses` filter (invalid tokens fail with 400, never fall
   back to an unfiltered table), both applied in SQL before pagination and
   before the total count, so list and count always agree.

2. **List filters and page position were lost on navigation (#784 A3).**
   PR #787 makes the URL the single authority for the submitted query on the
   question and exam lists: page and filters live in the URL, refresh and
   direct links restore the exact view, and detail/import/create pages
   return to the originating list URL through validated same-origin history
   state (no open-redirect surface). Strict positive-integer page parsing
   prevents `page=NaN` states.

3. **The Admin dashboard had no actionable queues (#784 B3).**
   PR #788 adds todo cards for the grading queue and the unresolved recovery
   queue, driven by the existing endpoints, gated by the actor's actual
   capabilities (hidden cards issue no requests), loaded once with manual
   refresh — no polling. Bounded counts are labeled "at least N" when the
   recovery cursor is not exhausted.

4. **A stale exam-extend conflict stranded the operator (#792).**
   When extending an exam that another operator had already closed, the
   Admin UI surfaced a raw 409 and kept the dialog open. PR #796 recognizes
   the `EXAM_EXTEND_NOT_ALLOWED` / `ALREADY_CLOSED` rejection, closes the
   dialog, refetches exam detail and tells the operator the view was
   refreshed; a failed refetch reports a retryable failure instead of
   claiming success.

5. **Same-exam deadline readers serialized behind an exclusive lock (#668).**
   Deadline reconciliation and answer saves read the exam authority under
   `FOR UPDATE`, queueing concurrent candidates of the same exam behind each
   other. PR #804 narrows the lock mode to `FOR SHARE`: reader transactions
   coexist, exam-authority writers keep full exclusion with the existing
   candidate-wins/save-wins linearization and 40001 retry semantics, and the
   seam is pinned as a terminal Exam-lock acquisition (no same-transaction
   upgrade, no deadlock). The change is backed by a recorded research rig
   with native Linux and WSL2 revalidation evidence.

6. **Tests could silently measure stale package output (#794).**
   PR #797 unifies `@exam/*` package exports (tests resolve workspace
   source directly; production resolves `dist`) with permanent
   source-freshness oracles and removes the second resolution path
   (`vitest.sourceAliases.ts`), documented as the resolution authority.

7. **The production image could carry more than runtime artifacts (#798).**
   PR #799 declares per-package `files` allowlists (API packages ship
   `dist`; `@exam/db` ships `dist` plus the PostgreSQL migrations), and adds
   `scripts/check-deploy-payload.mjs` — a positive closure check over the
   real `/app` tree (dist, migration journal + SQL, dependency closure,
   argon2 native binding) and a negative scan (no TS sources, test
   artifacts, env files or dev toolchain) — enforced by two CI jobs,
   including a no-network verification that every `@exam/*` resolves from
   `dist` in the built image.

8. **Local deployment credentials could be committed (#790).** PR #793
   adds `/.env.deploy` to `.gitignore`.

9. **October Node.js security release (#803).** The runtime base image,
   `.nvmrc` and CI move from Node 24.15.0 to 24.22.1.

## Notable changes

### Added

- Server-side pagination with search and status filters across the admin
  exam, candidate, course and results lists; new optional API query
  parameters `search` (candidates) and `statuses` (exams), validated and
  applied before pagination (#785, PR #786).
- URL-authoritative query state on the question and exam lists with
  validated return navigation (#784 A3, PR #787).
- Admin dashboard todo queues for grading and recovery, capability-gated
  and manually refreshable (#784 B3, PR #788).
- `GET /api/system/public-config` now projects the deployment's resolved
  product capability set (`product`: closed Standard catalog, revision 1)
  resolved by a fail-closed Standard preset resolver (#678 Phase 1,
  PR #802).

### Changed

- Candidate deadline reconciliation and answer saves read the exam
  authority under `FOR SHARE` instead of `FOR UPDATE`; writer exclusion,
  linearization and 40001 retry semantics are unchanged (#668, PR #804).
- Workspace `@exam/*` packages declare unified exports; tests resolve
  workspace source directly, production resolves `dist` (#794, PR #797).
- Runtime base image and `.nvmrc` move to Node.js 24.22.1 (PR #803).

### Fixed

- Admin lists show and page through records beyond the first 20; totals
  and page counts match the filtered server result set (#785, PR #786).
- Extending an already-closed exam now explains the conflict and restores
  a current view instead of stranding the operator on a raw 409 (#792,
  PR #796).

### Security

- Node.js runtime updated 24.15.0 → 24.22.1 (October 2026 security
  release, PR #803).
- `/.env.deploy` (local deployment credentials) is ignored by Git (PR
  #793).

### Deployment / operations

- The API production image payload is restricted to a declared allowlist:
  application `dist` plus the PostgreSQL migration journal/SQL, with a
  fail-closed CI oracle over the real image tree (dependency closure,
  argon2 native binding, no sources/tests/env files) and a no-network
  production-resolution verification (#798, PR #799).
- Both E2E shards and the production transport regression run in one
  pinned Playwright browser image derived from a single version authority
  (`apps/e2e/package.json` via `scripts/ci/playwright-runtime.mjs`); the
  duplicated browser/system-dependency install steps are removed, and the
  CI fails closed on image-identity drift (PRs #805, #806).

### Internal / infrastructure

- Permanent regression oracles for exam transitions (#784 C2, PR #789),
  grader assignment revocation/regrant and closed-exam projection (#791,
  PR #795), and the isolated-schema test lifecycle (BUG-FLAKE-005, #771,
  PR #773).
- Research and documentation: Architecture Atlas R0 semantic IR (#763,
  PR #768), #719 test-evidence-adequacy closeout (PR #782), flake
  register epistemic v2 (PRs #770, #772), R0.5 doc/code reconciliation
  (PR #761), #668 serialization research evidence (PR #804).
- `tsconfig.base.json` declares the shared TypeScript config schema
  (PR #807).
- No database migration in the `v0.0.9..master` file diff; the migration
  journal is unchanged (45 entries, invariant gate green).

## Known limitations

- **#678 Phase 1 only.** This release ships the closed Standard capability
  catalog, the fail-closed resolver and the read-only `public-config`
  projection. Phase 2 (authoritative server-side write guards), Phase 3
  (Minimal runtime) and Phase 4 (persisted deployment configuration with
  revision/CAS) are **not** implemented; Issue
  [#678](https://github.com/jnhu76/exam/issues/678) remains open. The
  projection is deployment availability only — it grants no permissions
  and changes no exam policy.
- The Architecture Atlas semantic IR (#768) and the #719/#668 research
  records are frozen evidence documents, not new runtime behavior.
- High-assurance Controlled/Strict profiles, `timed_sync`, multi-tenant
  platform features and the deferred capability set remain future work
  ([#293](https://github.com/jnhu76/exam/issues/293) and the current
  roadmap/implementation-status documents).
- No claim is made of site-specific production capacity, TLS activation,
  or production-volume restore certification.

## Upgrade notes

- No new database migration and no new required environment variable in
  this release; entrypoint auto-migration behavior is unchanged.
- `GET /api/system/public-config` responses gain a required `product`
  block. The version-paired `exam-web` image consumes it in lockstep;
  third-party clients that strictly validate this endpoint must accept the
  new field.
- Operators upgrade by deploying both version-pinned images
  (`ghcr.io/jnhu76/exam:v0.0.10` and `ghcr.io/jnhu76/exam-web:v0.0.10`)
  via the existing paired-image procedure (`init-production-env` rewrites
  `EXAM_IMAGE` / `EXAM_WEB_IMAGE` from `.release-version`; an explicit
  mirror value wins). No `latest` tag is published.
- Developers should follow the updated `.nvmrc` (Node 24.22.1); running
  the suite on older local Node versions is unsupported.
