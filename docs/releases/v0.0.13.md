# Exam v0.0.13

## Why this release exists

`v0.0.13` is a correctness-and-engineering-health release. It closes the
implicit state-machine audit remediation
([#927](https://github.com/jnhu76/exam/issues/927)), lands the build-first
development architecture ([#938](https://github.com/jnhu76/exam/issues/938),
[ADR-027](../adr/ADR-027-build-first-dev-execution.md)) with its permanent
drift guards ([#947](https://github.com/jnhu76/exam/issues/947)), completes
the secure-observability decision gates
([#864](https://github.com/jnhu76/exam/issues/864),
[#865](https://github.com/jnhu76/exam/issues/865),
[#925](https://github.com/jnhu76/exam/issues/925)) and delivers the
[#932](https://github.com/jnhu76/exam/issues/932) "Calm Console" first-wave
two-page implementation.

The release contains **no database migration and no environment-variable
change**; the only contract additions are additive (one machine error code,
the `x-request-id` response header). The user-visible product changes are
deliberately small: the admin dashboard now leads with the todo queues, and
the candidate exam list gains a visible title, an honest historical-best
badge, minute-precision exam windows and a 320px-safe layout.

## Problems solved

1. **Exam state transitions were reachable through inconsistent paths
   (#927, PR #929).** The static audit of 43 implicit lifecycle sites left
   five state-authority findings. PR #929 closes them: the exam-list scores
   affordance now reads the same `resolveAdminResultsAccess` verdict as
   `GET /exams/:id/scores` and the CSV export (which also calls the shared
   policy with `allowZeroGraded`, preserving the headers-only 200), with the
   additive machine code `UNRESOLVED_ATTEMPTS_EXIST` and one combined count
   query per listed exam; the deadline auto-submit tick and timer share one
   attempt-scoped episode whose identity/scope guards cover the pre-submit
   flush, the in-flight submit POST, the post-submit authoritative reload,
   unmount and heartbeat settlement — a stale episode can never submit,
   navigate, write the new attempt's state, release its `submittingRef`, or
   clear its deadline indicator; disrupt/restore moved onto a canonical
   transition table; force-submit candidates are pinned biconditionally to
   the planner; attempt/exam/enrollment update inputs are narrowed at
   compile time with a guarded PATCH cast; the architecture allowlist is
   tightened.

2. **Development could run against a silent partial build (#938, PRs
   #939/#940/#941, ADR-027).** `pnpm dev` is now the canonical managed
   entry (`turbo watch dev`): the first run builds the full workspace
   dependency closure before the API/web dev tasks start, source changes
   rebuild only the affected closure before managed tasks restart, and on
   the build rail `noEmitOnError` holds — a failed build emits no new
   artifacts and the managed tasks stay down until a rebuild succeeds. New
   explicit `dev:once` and `watch:dist` entries cover the one-shot and
   unmanaged-build cases. Contract, failure semantics and execution
   evidence are recorded in ADR-027 (ACCEPTED, with errata E1–E3).

3. **E2E could boot against stale internal-package `dist` (#938, PR #941;
   drift guards #939, provenance #947).** The E2E entry
   (`scripts/e2e/run.sh` `build_assets()`) rebuilds the complete workspace
   dependency closure (`pnpm build`) instead of only the `web`/`api`
   package builds — the build-side face of the stale-dist mixed-runtime
   class reported in #920 (that issue's HTTP 500 causality remains under
   its own RESEARCH_FIRST gate). The guards are machine-enforced:
   `config/build-graph-policy.mjs` wired into `pnpm lint:arch` requires the
   production Dockerfile build manifest to equal the workspace
   buildable-package set, workspace build helpers to be registered in
   turbo `globalDependencies`, and unsupported Dockerfile `RUN` forms to
   fail closed as named violations (PR #939); the e2e runner build closure
   itself is guarded in `lint:arch` by proving the `build_assets` call
   order, not text presence (PR #950); `@exam/db#build` is narrowed to its
   product dependency edge so verification builds do the minimum real work
   (PR #951).

4. **Client-event routes were stored and displayed as free strings
   (#864, PR #923).** `route` is now projected onto a closed vocabulary of
   49 SPA route templates at BOTH the ingest boundary and the
   proctor-timeline read (legacy rows re-projected on read; no data
   migration); unknown routes and malformed/non-http(s) URLs fail closed to
   `null`.

5. **Raw client URLs reached disk (#925, PR #926).** Pino request lines and
   the 19 authz/error log sites no longer persist raw client URLs — matched
   route templates or a fixed `(unrouted)` placeholder everywhere; the
   nginx access log uses an explicit privacy format (no `$request` /
   `$request_uri` / raw `$uri` / referer) recording the upstream
   `x-request-id`; the root 404 boundary replaces Fastify's URL-logging
   default. The nginx `error_log` keeps the Owner-decided `error` level
   (native upstream diagnostics; the bounded raw-request-line risk is
   accepted and documented).

6. **A refused save had no correlation carrier visible to the client
   (#865 scope 865-C, PR #924).** Every Fastify-managed response carries the
   server-owned `x-request-id` header (ADR-025 fourth correlation carrier):
   one root-scope hook reusing the existing request id — no second id is
   minted — with CORS exposing it only to the configured web origin;
   opt-in `api.getWithMeta`/`api.postWithMeta` client reads, and the
   TakeExamPage save path surfaces the rejection correlation id in
   candidate alerts and client telemetry. A save-failure investigation
   worked example (200 `accepted:false` → X-Request-Id → pino WARN →
   receipt/domain verification) ships in
   `docs/operations/save-failure-evidence.md`.

7. **The `rich-content-overflow` E2E flake had no causal model (#878, PR
   #923).** The root cause is causally proven (Chromium's internal
   key-scroll animation can commit its first frame 59ms–1078ms after the
   press under contention, and the lazy KaTeX fallback swap transiently
   flips the derived tab-stop state); all five fixed 150ms waits were
   replaced by an explicit trigger → state-change → settle oracle;
   registration in `docs/standards/test-flakes.md`
   (CASE-2026-11-09-878-KEYSCROLL-ORACLE).

8. **The admin dashboard buried the actionable work; the exam list hid its
   own title and over-claimed achievement (#932 first wave, PRs
   #943/#944/#945).** `/admin/dashboard` is reordered todo → 资产概览 KPI →
   近期考试 with quick actions in the `PageHeader` actions slot, so the
   actionable sections are the primary task anchor and the deciding
   asset-overview KPI stays first-screen (section order pinned by
   document-position tests, verified at 1440/390). `/exam/list` gains the
   visible page h1 我的考试 (shell-consistent with settings/start/result),
   a historical-best badge whose trophy renders only when
   `bestScore >= passingScore` (server-projected; below-passing demotes to
   secondary, so a zero score never carries achievement imagery), a
   mobile-only badge wrap that keeps exam titles at full 320px width
   (114px → 231px measured), minute-precision exam windows so ranges stop
   wrapping at 390px, and an empty state that names the cause and the next
   step. The minute-precision `formatDateTimeMinute` joins the product
   date/time authority as a pure extension — second digits are dropped,
   not rounded (`:59` stays in the same minute); second precision remains
   the default on proctor/recovery/audit surfaces that document exact
   ordering (PR #943). Server authorization, capability gating, result
   visibility and all data contracts are unchanged.

9. **Verification scripts had overlapping entry points (#948, PR #949).**
   The E2E, integration and lint surfaces converge on single semantic
   entries, removing parallel script paths.

10. **Test evidence carried unreachable states and duplicated harnesses
    (#933, #934, #935, #917).** The Recovery detail page collapses to the
    error/loading two-way split (PR #933); the TakeExamPage test harness is
    consolidated (PR #934); the recovery i18n vocabulary and error-key
    catalog resolution are pinned (PR #935); obsolete phase/milestone
    labels are removed from test titles (PR #917).

## Notable changes

### Added

- Server-owned `x-request-id` response header on every Fastify-managed
  response, CORS-exposed only to the configured web origin; opt-in client
  reads; the TakeExamPage save path surfaces the rejection correlation id
  (#865, PR #924).
- Additive machine error code `UNRESOLVED_ATTEMPTS_EXIST` on the results
  access path (#927, PR #929).
- Build-graph drift guards wired into `pnpm lint:arch` via
  `config/build-graph-policy.mjs`: the production Dockerfile build
  manifest must equal the workspace buildable-package set, workspace build
  helpers must be registered in turbo `globalDependencies`, and
  unsupported Dockerfile `RUN` forms fail closed as named violations
  (#938, PR #939).
- Minute-precision `formatDateTimeMinute` in the product date/time
  authority — seconds dropped, not rounded; second precision remains the
  default for ordering-documenting surfaces (#932, PR #943).
- Security-audit evidence archive for the secure-observability remediation
  (SHA256-pinned, sanitized copies; `docs/research/…-remediation/`)
  (#800 evidence basis, PR #922).

### Changed

- Client-event `route` is projected onto a closed vocabulary of 49 SPA
  route templates at the ingest boundary and the proctor-timeline read;
  unknown routes and malformed/non-http(s) URLs fail closed to `null`
  (#864, PR #923).
- Log privacy: pino request lines and the 19 authz/error log sites use
  matched route templates or `(unrouted)`; the nginx access log uses an
  explicit privacy format recording the upstream `x-request-id`; the root
  404 boundary replaces Fastify's URL-logging default (#925, PR #926).
- Dev rail: `pnpm dev` is the canonical managed entry (`turbo watch dev`)
  that builds the full dependency closure first; `noEmitOnError` holds on
  the build rail — a failed build never silently partial-releases; new
  `dev:once` and `watch:dist` entries; contract in ADR-027 (#938,
  PR #940).
- Admin dashboard order is todo → 资产概览 KPI → 近期考试, quick actions in
  the page header; section order pinned by document-position tests (#932,
  PR #945).
- Exam list: visible page h1, historical-best badge with trophy only at

## Upgrade notes

- **Read §2 of
  [`docs/deployment/upgrade-and-uninstall.md`](../deployment/upgrade-and-uninstall.md)
  first.** The upgrade is the existing paired-image procedure: deploy
  `ghcr.io/jnhu76/exam:v0.0.13` **and**
  `ghcr.io/jnhu76/exam-web:v0.0.13` together (`init-production-env`
  rewrites `EXAM_IMAGE`/`EXAM_WEB_IMAGE` from `.release-version`; no
  `latest` tag is published). Take the mandatory pre-upgrade backup
  (runbook §15) — it is also the rollback material (§2.5).
- **No database migration.** The schema is unchanged from v0.0.12; the
  entrypoint's migration step is a no-op on an up-to-date deployment.
- **No environment or configuration change is required.** The nginx
  access-log privacy format and the `/healthz` healthcheck are baked into
  the `exam-web` image; log consumers reading the access log or pino
  stdout should expect the new formats described above.
- **API surface growth (additive).** Every Fastify-managed response now
  carries `x-request-id` (CORS-exposed only to the configured web
  origin); the results access path can return the additive machine code
  `UNRESOLVED_ATTEMPTS_EXIST`. Clients that strictly validate response
  headers or error codes must accept these additions.
- **Behavioral notes.** The candidate exam list now shows a visible page
  title, a historical-best badge (achievement imagery only at or above
  the passing score) and minute-precision exam windows; the admin
  dashboard section order changed (todo first). No authorization,
  capability or data-contract change ships with them.
- **Rollback (§2.5).** No migrations are involved: rollback = redeploy the
  previous image pair (plus the standard pre-upgrade backup discipline).
  Beware the canonical-pin auto-revert on the next `init-production-env`
  run — pin by digest or edit after (§2.5).
- **Version skipping** stays supported by the migration journal replaying
  any backlog in order.
