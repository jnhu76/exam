# Exam v0.0.6

## Why this release exists

`v0.0.6` closes the gap between the frozen Exam semantic authority and the
artifacts that claim to implement it, and it converges the production
deployment surface to a single, minimal, operator-owned shape.

The first theme is **semantic authority adoption and conformance**. The
cross-boundary facts of the exam domain were frozen as EXSEM-001..020 and
adopted through ADR-021, then enforced against the implementation: candidate
result contracts are secret-safe, export uses submitted-answer authority,
draft-question references are distinguished from missing ones, demo grading
facts match the durable workset, and logged errors serialize to
classification fields. The two TLA+ model families were re-audited against
that frozen authority and repaired where they had drifted, including an
independent-review correction that restored the client/page authority
boundary in the recovery model.

The second theme is **one production edge, one operator surface**. Production
now runs a dedicated nginx reverse-proxy edge with a trusted client-IP
profile and a dedicated static-Web image, instead of relying on an implicit
exposure shape. The image entrypoint no longer silently seeds or reclassifies
the runtime; the residual deployment/backup/contract infrastructure was
deleted down to the minimal operator surface; configuration authority was
consolidated to one owner per runtime concern; and the dev/prod Compose
stacks were given distinct project identities so a same-checkout production
rehearsal can no longer capture the dev stack.

The third theme is **UI foundation and information architecture**: the visual
foundation contract (typography, geometry, surface, data-view grammar), the
recovery-scope projection, and AttemptDetail capability composition for
Proctor-reachable flows.

The fourth theme is **test-infrastructure convergence**: test evidence was
rationalized to minimum sufficient owners, DB-backed test lifecycle was made
worker-scoped and reusable, and the accompanying authority/comment drift was
closed. This is engineering hygiene, but it is the reason the release can
claim evidence rather than volume.

This remains a **pre-1.0** release.

## Problems solved

- **The frozen semantic authority was newer than the artifacts claiming
  conformance.** The formal models and several production contracts predated
  EXSEM. PRs #642/#643 adopted the authority and repaired the production
  boundaries it governs (candidate result secrecy, export answer authority,
  draft-question reference distinction, demo grading facts, error
  classification); PRs #657/#656 audited and repaired the two TLA+ families
  against the same authority (#656).
- **Production exposure was implicit.** PR #628 adds a real nginx edge
  (`deploy/nginx/edge.conf`) with a trusted client-IP profile
  (`TRUSTED_PROXY_CIDRS`) and a dedicated static-Web image/service
  (`EXAM_WEB_IMAGE`, `deploy/nginx/web.conf`) instead of serving the SPA
  through the API process (#585).
- **The production image could silently seed or reclassify itself.** PR #636
  removes the entrypoint automatic-seed interface: `RUN_SEED` /
  `FORCE_APP_MODE` no longer derive an application mode, and any non-empty
  value fails the container before migration. Production first-admin remains
  `bootstrap-admin`; test/e2e data is an explicit host command.
- **Same-checkout dev and production Compose stacks collided.** PR #646 pins
  distinct project identities (`exam-dev`, `exam-prod`); previously both
  computed the directory-derived project `exam`, so a production rehearsal
  could recreate dev containers and steal published ports (#631).
- **Configuration had more than one owner per runtime concern.** PR #633
  consolidates configuration authority; invalid explicit values fail fast
  instead of silently becoming defaults (#632).
- **The operator surface carried unused machinery.** PR #630 deletes residual
  deployment/backup/contract infrastructure (including the PITR helper and
  two superseded deployment documents) down to the minimal operator path;
  PR #627 consolidates Compose/E2E execution surfaces (#626); PR #635 audits
  the `package.json` script surface to caller-evidenced entries (#634).
- **AttemptDetail exposed capability-composition defects to Proctor flows.**
  PR #616 closes the composition gap where a Proctor-reachable flow could see
  affordances its capability set did not authorize (#612).
- **The recovery scope contract was not discoverable in the projection.**
  PR #608 converges the admin/candidate recovery-scope contract and
  information architecture (#606).
- **DB-backed test lifecycle paid a physical cost per test file.** PRs
  #649/#651 introduce worker-scoped migrated-database reuse and remove
  fixture-only physical DB lifecycle, cutting reset cost without weakening
  isolation (#648).
- **A `@exam/db` failurePath flake was unresolved.** PR #655 makes the
  backend-release proof eventual and removes the `pg_stat_activity` race; the
  failure mode is recorded in the flake registry (#650).
- **Test evidence volume obscured test evidence.** #609–#611 audits and PRs
  #617/#618/#619/#622/#623/#625 close authority drift and prune evidence to
  named owner boundaries (#613, #614, #615, #620, #621, #624).

## Notable changes

### Added

- Production nginx reverse-proxy edge with a trusted client-IP profile
  (`TRUSTED_PROXY_CIDRS`) and a dedicated static-Web image/service
  (`EXAM_WEB_IMAGE`, `deploy/nginx/web.conf`, `deploy/nginx/edge.conf`).
- `.env.production.example` as the production deployment env template
  (replacing `.env.deploy.example`).
- A distinct Compose project identity per stack: `exam-prod` (production) and
  `exam-dev` (dev).
- Frozen Exam semantic authority (EXSEM-001..020) with ADR-021 as the
  adoption/supersession record.
- Worker-scoped migrated-database reuse for ordinary `@exam/db` tests.

### Changed

- Candidate result and attempt contracts are secret-safe: standard answers,
  rubrics, and management-only fields cannot leave the server through
  candidate-facing contracts.
- Score export uses submitted-answer authority; demo seed grading facts align
  with the durable workset; missing draft-question references are
  distinguished from absent ones.
- Logged errors serialize to classification fields instead of leaking raw
  structure.
- In production the edge is the only public ingress: `/` is proxied to the
  static Web runtime (`web:4173`) and only `/api/` reaches Fastify
  (`app:3000`), with request-time upstream name resolution so container
  recreation on upgrade cannot leave a stale upstream address.
- Configuration authority is consolidated to one owner per runtime concern;
  invalid explicit values fail fast.
- The recovery TLA+ model treats the client's applied `CandidateTakeSnapshot`
  as the page business authority, and models canonical deadline crossing
  without materializing durable state.

### Fixed

- AttemptDetail capability composition for Proctor-reachable flows (#612).
- Recovery scope discoverability mismatch between admin and candidate
  projections (#606).
- Compose project-name collision between same-checkout dev and production
  stacks (#631).
- The `testDbWorkerScoped.failurePath` `pg_stat_activity` race (#650).
- Worker-DB bootstrap lifetime for the API-coverage hook-timeout family.
- Formal-model drift against the frozen semantic authority, including the
  over-constrained recovery invariant that had erased a legitimate
  asynchronous deadline window (#656).

### Removed

- The image entrypoint automatic-seed interface: `docker-entrypoint.sh` no
  longer runs a seed or derives `APP_MODE` from `RUN_SEED` / `FORCE_APP_MODE`;
  any non-empty value now fails the container before migration.
- Residual deployment/backup/contract infrastructure beyond the minimal
  operator surface, including the PITR enablement helper and the superseded
  `docs/deployment/backup-and-recovery.md` and `docs/deployment/gates.md`.
- `docker-compose.build.yml` and `docker-compose.test.yml`; the dev-test
  topology is host-native.
- `.env.deploy.example` and `.env.test.example` (replaced by
  `.env.production.example` and by CI/E2E-provided environment respectively).
- Stale `timeGrant` / `GrantExtension` / `TimeGrantNeverDecreases` formal
  scaffold and dead recovery actions (`MarkDisrupted`, `NetworkDown`,
  `NetworkUp`) that were unreachable from every gated specification.

### Security

- Candidate-facing result contracts are secret-safe (EXSEM-017).
- Sensitive audit-evidence and auth-context oracle gaps are closed with
  deterministic regressions (#613).
- Production runs behind a single reverse-proxy edge whose trusted client-IP
  ranges are operator-declared; client-IP trust is no longer implicit. The
  edge **replaces** `X-Forwarded-For` with the real client address rather than
  appending to it, so a client-supplied chain cannot enter the application's
  trusted-proxy walk and forge audit or rate-limit identity.
- The production image fails closed on any attempted runtime reclassification
  or implicit seeding.

### Deployment / operations

- Two **one-time breaking renames** must be applied when upgrading an
  installation created before this release (env file and Compose project
  identity); both are documented step-by-step in
  `docs/deployment/upgrade-and-uninstall.md` §2.2 (steps 0b and 0c).
- The operator image pins follow `.release-version`; `init-production-env`
  fills blank values only and never re-secrets an existing
  `.env.production`.
- Production first admin remains `bootstrap-admin`; there is no production
  seed path.

### Internal / infrastructure

- Test evidence pruned to minimum sufficient owner boundaries; authority and
  comment drift closed (#609–#625).
- Fixture-only physical DB lifecycle removed from DB tests; worker-database
  reuse adopted (#648/#649/#651).
- Package-script surface audited to caller-evidenced entries (#634).
- Repository release tagging policy is unchanged: immutable annotated tag,
  no `latest` image tag.

## Verification

Release membership is defined by ancestry from the published `v0.0.5` tag
target (`44d78d8ec6e6160164f033bdc2fc3aa6a1ce07a6`) through the pre-release
`master` (`c5879f178d71aa9e5db50901d7105f5ab85b9b1a`). The exact range contains
129 commits before this metadata-only release preparation.

The release-preparation change is intentionally limited to `.release-version`,
`CHANGELOG.md`, and this version-specific release record. Its exact PR head
must pass normal repository CI before merge.

After merge to `master`, `.github/workflows/release.yml` validates the release
contract on the exact merge SHA, builds **both** images (API `runner` and web
`web-runner`) before any irreversible publication step, pushes
`ghcr.io/jnhu76/exam` and `ghcr.io/jnhu76/exam-web` at `v0.0.6` plus the
`sha-*` alias (deliberately no `latest`), creates or verifies the immutable
annotated `v0.0.6` tag at that exact commit, and creates the GitHub Release
from this file. Publication is complete only after the workflow succeeds and
the tag target, the Release, and the image digests are verified.

The release workflow runs **no deployment simulation**; the production
deployment itself is the acceptance surface (`docker compose config`
interpolation plus the operator runbook §11 smoke test).

For the semantic-conformance work in this release the formal families were
re-run on the pinned toolchain (tla2tools v1.7.4 / TLC2 2.19):

```text
pnpm formal:recovery         safety PASS · route PASS · submission PASS
                            4/4 expected counterexamples reproduced
                            liveness PARTIAL (documented, pre-existing)
pnpm formal:operator-grant   server PASS · client PASS
                            10/10 counterexamples · 2/2 witnesses
```

## Known limitations

- **`timed_sync` is still not product-activated.** It remains a reserved
  vocabulary value (EXSEM-019): the publish gate rejects it, and
  `docs/contracts/timed-sync-semantics.md` is a dormant design contract, not
  an implementation authorization.
- **Single-node / single-tenant deployment remains the supported product
  shape.**
- **Published images remain linux/amd64 unless the release workflow is
  changed separately.** No multi-arch claim is made.
- **The recovery TLA+ liveness property remains a documented PARTIAL.** The
  environment-fairness gap (`LoseResponse` racing an applicable authoritative
  reload) is pre-existing and has recorded resolution options; it is not a
  protocol defect and was deliberately not "fixed" in this release.
- **`bounded_grace` deadline-rescue reachability still has no formal owner**
  anywhere in `formal/`; the recovery family states that exclusion explicitly
  rather than implying coverage.
- **External PostgreSQL is still not a supported operator path**; upgrades run
  against the bundled `db` service.
- **Pre-1.0 baseline.** This release converges authority and deployment
  surfaces; it is not a claim that the generic-product roadmap is complete.

## Upgrade notes

`v0.0.5 → v0.0.6` adds **no PostgreSQL migrations** and does **not** change the
PostgreSQL major (still `postgres:18.4-bookworm`), so no dump/restore cycle is
required beyond the mandatory pre-upgrade backup.

Two **one-time breaking renames** apply to installations created before this
release. Both are idempotent and are documented step-by-step in
`docs/deployment/upgrade-and-uninstall.md` §2.2:

1. **Deployment env file renamed** (step 0b). The deployment env file is now
   `.env.production`; the old `.env.deploy` must be renamed **before** running
   `node scripts/init-production-env.mjs`, otherwise a fresh file with new
   secrets would be created against the retained `PGDATA` and JWT logins plus
   database authentication would break. `init-production-env` only fills blank
   values — an existing `JWT_SECRET`, `POSTGRES_PASSWORD`, or any explicit
   operator override is never regenerated or rotated.
2. **Compose project identity pinned** (step 0c). The production stack now
   runs as project `exam-prod` (dev: `exam-dev`). The next `up -d` creates new
   containers under that name; the old stateless `exam` containers keep
   holding the published ports and must be removed once, or the new nginx edge
   cannot bind. Data is unaffected — the data root is a bind mount outside the
   containers.

Additional operational changes to account for:

- **A new image must be pinned.** Production now runs the edge plus a
  dedicated static-Web service, so `EXAM_WEB_IMAGE` is required in addition to
  `EXAM_IMAGE`. `node scripts/init-production-env.mjs` derives both from
  `.release-version`; air-gapped installs must `docker load` both images with
  references equal to the pins.
- **The container contract hardened (breaking for scripted deployments).**
  `RUN_SEED` / `FORCE_APP_MODE` no longer select an application mode; a
  non-empty value fails the container before migration. Use
  `bootstrap-admin` for the first production admin, and
  `pnpm --filter @exam/api db:seed:e2e` against the e2e/test database for
  test data.
- **Trusted proxy ranges must be declared.** With the nginx edge, client-IP
  trust is explicit via `TRUSTED_PROXY_CIDRS` in `.env.production` (see
  `.env.production.example`).
- **Removed operator machinery.** The PITR enablement helper and the
  superseded deployment documents are gone; the supported backup/restore path
  is `./scripts/db-backup.sh` as described in the runbook.

Version skipping remains supported by default: migrations are
forward-append-only and the journal applies any backlog in order. There is no
mandatory intermediate version for this release.
