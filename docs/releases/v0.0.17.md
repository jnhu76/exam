# Exam v0.0.17

## Why this release exists

`v0.0.17` is a focused security and development-quality maintenance release following `v0.0.16`. It makes logout revocation failure explicit instead of reporting success, improves React test lifecycle synchronization, and adds incrementally executed Web lint checks without replacing the existing full CI gates. No part of the ongoing modularization (#678) or unified admission design (#645) is presented as implemented.

## Changes

### Security and correctness

- **Logout revocation fails closed** ([#1082](https://github.com/jnhu76/exam/pull/1082), [#1079](https://github.com/jnhu76/exam/issues/1079)): if the authenticated user's authorization-epoch revocation cannot be durably written, `POST /auth/logout` returns HTTP 503 `AUTHZ_UNAVAILABLE` and does not clear the cookie or claim successful logout. Normal successful logout remains HTTP 204; invalid or already-revoked tokens remain idempotent.
- The API response contract, logout behavior tests, browser auth state and end-to-end failure coverage were updated together. Applications integrating with the logout endpoint should handle HTTP 503 explicitly, rather than treating it as a successful logout.

### Tests and development quality

- **React test lifecycle cleanup** ([#1085](https://github.com/jnhu76/exam/pull/1085)): tests using asynchronous UI updates now synchronize with the relevant lifecycle so React `act(...)` warnings do not obscure genuine failures.
- **Incremental Web quality gate** ([#1086](https://github.com/jnhu76/exam/pull/1086)): staged Web TS/TSX files run the existing ESLint configuration, which now enforces `react-hooks/rules-of-hooks` alongside the existing `exam-ui/*` checks. The existing pre-push TypeScript/OpenAPI checks and full CI remain authoritative. Historical compatibility directives are preserved.
- **Diff-scoped Code Review** ([#1086](https://github.com/jnhu76/exam/pull/1086)): the existing review skill now defaults to comparing the proposed HEAD with the merge-base of its target branch and reading only required adjacent context.

### Release infrastructure

- **Release-note rendering guard** ([#1081](https://github.com/jnhu76/exam/pull/1081)): historical notes were normalized to avoid unintended GitHub line breaks, and the release pipeline checks new release notes before publishing.

## Upgrade notes

- **No new database migration or deployment configuration key** was introduced between `v0.0.16` and this release. Keep using the existing deployment and backup process.
- **Logout failure is now explicit**: frontends or external consumers must not interpret HTTP 503 from `POST /auth/logout` as a completed session revocation. The first-party Web client retains the authenticated state when revocation cannot be confirmed.
- **Upgrading across `v0.0.16`**: environments that have not yet applied database migration `0047_candidate_fields_org_identity_uidx` still require the read-only duplicate-identity precheck and normal migration procedure described in [v0.0.16 upgrade notes](v0.0.16.md). Do not skip that deployment hold merely because this release adds no migrations.
- **Rollback**: roll back to the previously verified API and Web image pair using the repository's existing version-pinning, backup and upgrade procedures. Rolling back the code also restores the old logout failure semantics; assess the security implication before rollback.

## Scope and limitations

- This release does not implement account-free roster admission, external launch, or the modularization work tracked by [#645](https://github.com/jnhu76/exam/issues/645) and [#678](https://github.com/jnhu76/exam/issues/678).
- The new Web lint rule does not prove asynchronous lifecycle, authorization, database transaction, or cross-package correctness; the existing deterministic checks, targeted tests and review obligations remain required.
