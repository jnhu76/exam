# Exam v0.0.4

## Why this release exists

`v0.0.4` turns the increasingly capable Exam codebase into a more coherent
product baseline. Since `v0.0.3`, three programs dominated the range.

First, the user-facing message and error system was rebuilt onto a frozen
contract. A repository-wide adversarial audit (#413) was converted into seven
remediation PRs (C0–C6) that define one documented authority for user-facing
messages, give errors machine-readable semantics end to end, localize their
web rendering, and enforce the contract with tooling so it cannot silently
decay.

Second, the Admin UI gained explicit shared spatial, navigation, and table
contracts. The individual screens had been converging page by page; this
release closes the system: page geometry, table sizing and tier negotiation,
row action capacity, dialog/form/toolbar vocabularies, a mobile card
representation for management lists, structural route→page metadata coverage,
and navigation current-location/scroll continuity — each backed by
browser-level regression gates rather than convention.

Third, the timing-mode umbrella (#291) was closed with `deadline` and
`untimed` fully covered at the candidate runtime level, while operational
notifications (candidate exam assignment), a 390px responsive baseline for
candidate and Admin surfaces, and a hardened test/deployment evidence base
round out the product story.

This is still a **pre-1.0** release. The synchronized `timed_sync` mode
remains a latent, non-authorable kernel pending durable admission-queue work,
and the UI governance campaign's final issue closures remain under human
review.

## Problems solved

- **User-facing messages had no single authority.** The message/error contract
  is now frozen (D0.1–D0.13), API errors carry machine semantics, known
  machine errors render localized copy in the web app, semantic authority was
  cleaned up, enforcement gates catch regressions, and residual violations
  were closed (#413, C0–C6).
- **The UI behaved correctly page-by-page but lacked shared spatial
  authority.** Overflow measurement, row action capacity, dialog and form
  spatial vocabularies, table role matrix/tier negotiation/fit equation,
  toolbar control sizing, and page-role geometry were consolidated, each with
  durable regression gates (#452, #453, #454, #455, #458, #459, #460).
- **Management lists had no mobile representation.** Narrow viewports now get
  a typed card representation with an explicit priority→field mapping instead
  of a squeezed table (#457).
- **Route metadata could silently fall back to a generic title.** Router→
  pageMeta completeness is now structurally enforced, and previously omitted
  routed pages (including the grading queue) register real titles (#439 V5,
  #490).
- **A long Admin navigation could lose the user's current location.**
  Navigation families, current-location semantics (including routed
  descendants), and sidebar scroll continuity now have explicit contracts and
  browser gates (#494).
- **Below ~400px the product was effectively unusable.** Candidate and Admin
  surfaces now have a verified 390px baseline (#306), and primary buttons
  preserve the keyboard focus ring required by WCAG 2.4.7 (#412).
- **Bulk enrollment failed confusingly on duplicate input.** Duplicate
  `candidateIds` within one payload are classified as `DUPLICATE` skips with
  per-row results (#408).
- **Candidates learned about new exams only by polling the UI.** Assignment
  now triggers an operational notification email, delivered through converged
  production renderers (#299, #300).
- **Timing-mode correctness relied on unit evidence alone.** Candidate-runtime
  E2E coverage for `deadline` and `untimed` completed the #291 program; the
  umbrella issue is closed with `timed_sync` explicitly still latent (#405).
- **Test infrastructure was flaky at the concurrency knee.** `@exam/db` worker
  parallelism is capped at the measured lifecycle-lane knee (#463), and the
  fresh-install gate's email assertion uses a deterministic send-entered
  witness instead of a one-shot log grep, with the ADR-011 claim-vs-execution
  boundary documented (#482).
- **Visual evidence could false-pass and deployment findings lacked a home.**
  A multi-role multimodal screenshot patrol harness with contact-sheet
  artifact-integrity gates landed (test infrastructure), and Docker black-box
  discovery became a periodic campaign with a canonical authority (#466,
  #476).
- **Documentation authority had drifted.** ADR authority precedence is now
  defined, the ADR set has a map and grouped convergence (foundation group
  001–004, RBAC, queue authority), snapshot timing is aligned with
  publish-time freeze, and agent-governance debt received a corrective
  (#414/#415 and related docs PRs).
- **A dead dependency invited misuse.** The unused `@fastify/jwt` dependency
  was removed so authorization keeps a single implementation (#436).

## Verification

Release membership was audited by ancestry from published tag `v0.0.3`
(`b7c535d6740a791c1502b688d414971f353bff25`) through current `master`
(`3c24da32a9ec33d2b993d50de8423c095270365a`) before the release-metadata
commit: 38 merged PRs plus four direct commits (two of which are the
accidental placeholder add/remove pair, cancelled out). Issue close dates were
not used as release-membership evidence.

The release-preparation PR is metadata-only: `.release-version`,
`CHANGELOG.md`, and this version-specific release record. Before merge it
must have the normal repository final-head gates green, including static
checks, typecheck, and the exact-head CI required gates (unit, integration,
E2E shards, deployment fresh-install gate). Older-head CI is not release
evidence.

After merge to `master`, `.github/workflows/release.yml` validates the
release contract on the exact merge SHA, creates/verifies the immutable
`v0.0.4` tag, creates the GitHub Release from this file, and publishes
`ghcr.io/jnhu76/exam:v0.0.4` plus the `sha-*` alias. Publication closeout
must verify tag target, workflow success, image digest, and pullability.

## Known limitations

- **`timed_sync` is not product-activated.** The mode remains a latent enum
  value excluded from authoring; activation waits on the durable
  admission-queue work. The #291 umbrella is closed, but synchronized starts
  cannot be authored or taken in this release.
- **No durable admission queue.** High-assurance queued admission remains
  roadmap work (#292).
- **Single-node, single-tenant deployment only.** One deployment represents
  one organization; multi-instance/multi-tenant platformization is a later
  decision (#311).
- **Rich-content asset upload is not included.** The content protocol is
  asset-ready, but a canonical image/file Asset authority is separate work.
- **Published images are linux/amd64 only.** The release workflow publishes
  no multi-arch manifest; other architectures use the documented source-build
  path.
- **Pre-1.0 baseline.** Generic-product and high-assurance roadmap work
  continues under Issue #333.
- **UI governance campaign closure is in flight.** The implementation for
  #439/#445/#461/#490/#494 is on `master`, but those campaign issues remain
  open pending final human review; automated patrol complements rather than
  replaces manual visual acceptance.

## Upgrade notes

`v0.0.3 → v0.0.4` introduces **no new database migrations** (verified: the
migration set through `0041_phase_b_sync_started_at.sql` is identical in
v0.0.3 and this release). There is no schema change, no manual SQL, and no
PostgreSQL major-version change.

No new manual deployment step is required. Take the normal mandatory
pre-upgrade database backup, then:

```bash
git pull
node scripts/generate-env.mjs
docker compose --env-file .env.deploy pull
docker compose --env-file .env.deploy up -d --remove-orphans
```

Existing `.env.deploy` files remain valid; newly introduced email/settings
keys keep runtime-equivalent defaults. The removed `@fastify/jwt` dependency
is internal and has no operator-visible effect. No intermediate release is
required.

Rollback remains forward-only: restore the pre-upgrade database backup,
return to the v0.0.3 checkout, and redeploy the v0.0.3 image.
