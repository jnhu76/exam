# Exam v0.0.9

## Why this release exists

`v0.0.9` is a bounded post-`v0.0.8` stabilization release. It removes
candidate-visible trust and accessibility-of-controls regressions found after
the Rich Subjective rollout, and reconciles repository-level configuration
layout and active roadmap navigation without changing the Exam semantic kernel.

The release is based on the actual ancestry
`v0.0.8` (`9f5140f1a94d876020f5e56ddf75c1ce316821b1`) →
preparation base `master` (`2cc83ab44a35538d7d974d45c66e7023f12e0116`):
25 commits containing five merged PRs (#750, #752, #753, #754, #755).
The release-preparation merge adds only the three release-authority files.

## Problems solved

1. **Non-user Rich editor state changes created false answer facts (#697).**
   Tiptap `setEditable` could emit an update with no document change while
   mounting or toggling disabled state. The candidate UI then considered a
   previously unanswered Rich question answered and scheduled an unnecessary
   SaveAnswer POST; restoring a saved answer could advance version/clientSeq
   without candidate edits. PR #755 suppresses that emission while retaining
   real document updates. Its targeted test uses the actual editor extension
   set and observed RED-before/GREEN-after behavior.

2. **Candidate result text misrepresented a submitted exam (#698).**
   For a hidden, non-graded result, the historical `hiddenReason=not_started`
   catch-all was wrongly presented as literal state even after a deadline
   submission. PR #753 derives lifecycle wording from the authoritative
   attempt `status` and reserves hiddenReason for the graded-result
   publication gate. The engine's result-visibility decision, wire enum,
   OpenAPI and suppression of hidden scores remain unchanged.

3. **Narrow candidate screens obscured Rich commands (#699).**
   A nowrap formula toolbar overflowed narrow answer cards; wrapping
   containment alone would not fix toolbar discoverability, and a first
   horizontal-scroller solution hid the More control itself. PR #752 uses
   actual toolbar container width for command allocation and keeps the More
   menu reachable. Long unbroken tokens in Rich prompts/options now wrap;
   the fix was corrected after real-browser measurements at 320/375px.

4. **Repository authority/navigation could mislead maintainers.**
   PR #750 relocates only three root-level config helper modules under
   `config/`, updates their consumers, and narrows misleading Vitest
   environment documentation. PR #754 reconciles the completed #584/#587
   status in navigation and explicitly preserves #293 high-assurance
   capabilities as future, unproven work. Neither PR authorizes a new
   product preset, execution tracker, runtime config rule, or server behavior.

## Notable changes

### Fixed

- Non-user editor events no longer produce false Rich answer save/version
  changes.
- Candidate result UI distinguishes in-progress, submitted, disrupted,
  voided and other supported attempt states without expanding the wire contract.
- Narrow candidate editor controls remain reachable via width-aware More
  allocation and Rich read-only content wraps long tokens.

### Changed

- Repository-scoped config/test helper locations and their import paths.
- Current roadmap/documentation navigation for completed historical programs.

### Internal / infrastructure

- Targeted editor, candidate result/score and toolbar regression assertions.
- No database migration in the `v0.0.8..master` file diff.
- No new Exam runtime role, permission or semantic authority introduced.

## Known limitations

- This release does not activate Controlled/Strict high-assurance profiles,
  `timed_sync`, multi-tenant platform features, or deferred capabilities.
  See [#293](https://github.com/jnhu76/exam/issues/293) and the current
  implementation-status/roadmap documents.
- Rich formula convenience behavior beyond the shipped Phase-U contract
  (global input shortcuts, full MathLive ↔ expert-source bidirectional sync)
  remains decision-gated in [#756](https://github.com/jnhu76/exam/issues/756).
- [Architecture Atlas #757](https://github.com/jnhu76/exam/issues/757)
  is a future design effort; it is **not** a v0.0.9 product feature.
- No claim is made of site-specific production capacity, TLS activation,
  production-volume restore certification, or complete platformization.

## Upgrade notes

- No new database migration or new required environment variable in this
  bounded release.
- Operators should deploy both version-pinned `exam` and `exam-web`
  images using the existing paired-image procedure, not an unpinned
  `latest` tag.
- Developers using repository-level config helper paths should use the new
  `config/` location; this relocation does not change production env
  precedence or accepted values.
