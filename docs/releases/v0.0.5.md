# Exam v0.0.5

## Why this release exists

`v0.0.5` is a hardening release that turns several previously provisional
runtime boundaries into durable product contracts.

The largest functional change is queue admission. The old process-local queue
is replaced by PostgreSQL-backed admission state with restart-safe membership,
a write-once admission fact, atomic consumption at attempt start, and a
fail-closed start gate. This removes the single-process authority that could
lose ordering on restart or admit too many candidates across processes.

The second theme is boundary hardening. The HTTP surface now has one routing
authority for API, docs, static assets, and SPA navigation; persisted exam
state vocabularies are backed by database CHECK constraints; managed runtime
profiles no longer inherit developer `.env` state; and explicit numeric
configuration fails fast instead of silently falling back.

The third theme is UI convergence. Assignment affordances now reflect both
actor capability and target role state, the final #582 visual decisions were
implemented and regression-reviewed, dense-table column allocation defects
were corrected, and audit-log / invitation table values now use semantic
value-grammar owners rather than the generic `type` role.

This remains a **pre-1.0** release. `timed_sync` still exists only as a latent
kernel and remains non-authorable; the durable admission runtime shipped here
is one prerequisite for a later activation decision, not activation itself.

## Problems solved

- **Queue admission was process-local.** PR #521 replaces the in-memory queue
  with durable `exam_admissions` rows, deterministic join ordering,
  write-once `admitted_at`, atomic attempt-start consumption, and restart /
  multi-process evidence. `requireQueue` now has a durable authority instead
  of a module-level Map (#292).
- **HTTP surface identity could be rediscovered by URL heuristics.** PR #499
  establishes one Fastify routing authority: `/api` owns canonical JSON 404s,
  the API-reference namespace remains router-owned even when docs are disabled,
  static assets/fonts have explicit cache scopes, SPA fallback is GET/HEAD
  navigation only, and API rate limiting is scoped by router composition
  rather than raw-URL classification (#429, #500; ADR-020).
- **Persisted lifecycle vocabularies were weakly bounded.** PR #555 / migration
  `0043` adds fail-closed CHECK backstops for exam, enrollment, attempt, and
  grading-status value sets while keeping engine commands as the sole
  transition authority. Historical `status='grading'` residue is never
  silently rewritten; the migration includes an explicit operator recovery
  runbook (#542).
- **Managed test/e2e processes could inherit developer `.env` configuration.**
  PR #565 makes managed profiles skip developer `.env` import and makes the WSL
  runner explicitly own its API shard port/origin projection.
- **Invalid explicit numeric configuration could silently become a default.**
  The #566–#570 configuration hardening wave (PRs #573–#578) makes invalid
  port/rate-limit values fail fast, narrows production-only/no-op settings, and
  removes dead feature-flag plumbing with bidirectional config-contract gates.
- **Assignment UI exposed stale or unauthorized affordances.** PR #581 makes
  Teacher→Course and Grader→Exam actions depend on the target's active role set
  and the actor's capability, keeps view-only dialogs read-only, gates score
  export separately, fixes inactive-target affordances, and provides real
  pagination/search for large catalogs (#548).
- **Admin-table values could paint into neighboring columns.** PR #597 fixes
  the #590 role-pill and date-range allocation failures; PR #599 gives audit
  actions their own `action-label` grammar-class owner, moves machine
  `targetType` values to `short-id` with accessible middle truncation, and
  renders invitation expiry through the product date/time authority (#598).

## Notable changes

### Added

- Durable `exam_admissions` persistence and restart-safe queue admission
  semantics (migration `0042`).
- Database CHECK backstops for persisted status vocabularies (migration `0043`).
- Audit action-label vocabulary/copy completeness and accessible raw-key
  compatibility presentation.
- Browser/runtime regression ownership for the table cell-fitting defects that
  previously crossed shared column borders.

### Changed

- API/docs/static/SPA routing is composed by router scope rather than raw URL
  re-parsing.
- Managed runtime profiles reject developer `.env` leakage and invalid explicit
  numeric settings fail fast.
- Staff assignment and score-export controls reflect actual capability and
  target-role truth instead of role/cache surrogates.
- Admin visual baseline: 15px governed body/table text, 6px primary-control
  radius, 500-weight tags, surface-owned modal/panel backgrounds, and corrected
  semantic table allocations from the #582/#590/#598 chain.

### Fixed

- Restart and multi-process admission divergence, including the legacy case
  where a waiting candidate could become first after process loss.
- API-reference namespace escape into the SPA shell when docs are disabled.
- WSL E2E port ownership failures caused by root `.env` contamination.
- Silent fallback from invalid explicit port/rate-limit values.
- Assignment/export UI actions that the server would inevitably reject.
- Role-pill, date-range, audit-action, audit-target and invitation-expiry table
  containment/semantic-owner defects.

### Removed

- The process-local exam queue authority.
- Dead product feature-flag configuration with no runtime consumers.
- Raw-URL policy classifiers that duplicated router identity.

## Verification

Release membership is defined by ancestry from the published `v0.0.4` tag
target (`a24d288c05b53828d8f7240c66b6a9092ba4e4fe`) through the pre-release
`master` (`03c99cacdc779fb5158f092e865ab1bf33032b2b`). The exact range contains
245 commits before this metadata-only release preparation.

The release-preparation change is intentionally limited to `.release-version`,
`CHANGELOG.md`, and this version-specific release record. Its exact PR head must
pass normal repository CI before merge.

After merge to `master`, `.github/workflows/release.yml` validates the release
contract on the exact merge SHA, runs disposable fresh-install acceptance,
creates/verifies the immutable annotated `v0.0.5` tag, creates the GitHub
Release from this file, and publishes `ghcr.io/jnhu76/exam:v0.0.5` plus the
`sha-*` alias. Publication is complete only after the workflow succeeds and the
tag target / release are verified.

## Known limitations

- **`timed_sync` is still not product-activated.** The synchronized-time kernel
  and durable admission runtime exist, but the canonical authoring validator
  still rejects `timed_sync`; activation remains a separate B2 decision.
- **Single-node / single-tenant deployment remains the supported product
  shape.** The infrastructure review did not adopt MQ, event-bus, read-cache,
  or multi-instance platform machinery.
- **Published images remain linux/amd64 unless the release workflow is changed
  separately.** No multi-arch claim is made by this release.
- **Pre-1.0 baseline.** This release hardens contracts; it is not a claim that
  the generic-product roadmap is complete.

## Upgrade notes

`v0.0.4 → v0.0.5` adds two forward-only PostgreSQL migrations:

- `0042_exam_admissions.sql` — creates the durable admission authority. There
  is no backfill for the old in-memory queue because that state was ephemeral;
  candidates simply join the durable queue when required. Existing in-progress
  attempts resume without admission.
- `0043_persisted_state_status_checks.sql` — installs CHECK constraints for
  persisted status vocabularies. It **fails closed** if historical rows contain
  values outside the accepted sets, including legacy `status='grading'` crash
  residue. It never silently rewrites those rows. If the preflight fails,
  follow the operator recovery runbook embedded at the top of migration `0043`,
  disposition the affected rows explicitly, then rerun the migration.

For a normal clean database no manual SQL is required: take the mandatory
pre-upgrade backup and deploy normally; the application entrypoint applies
forward migrations.

Configuration parsing is stricter in this release. Explicit invalid values such
as non-numeric/out-of-range `APP_PORT` / `DEV_API_PORT` or non-positive
rate-limit settings now stop startup instead of falling back. Fix such values
before redeploying. Removed dead `FEATURE_*` settings no longer have product
semantics.

Standard deployment sequence:

```bash
git pull
node scripts/generate-env.mjs
docker compose --env-file .env.deploy pull
docker compose --env-file .env.deploy up -d --remove-orphans
```

Rollback remains forward-only: restore the pre-upgrade database backup, return
to the `v0.0.4` checkout/image, and redeploy that version. Do not attempt to
reverse migrations in place.
