# Exam v0.0.7

## Why this release exists

`v0.0.7` is the deployment-topology convergence release. It closes the gap
that `v0.0.6` left between the production `docker-compose.yml`, its
documentation, and the reality a LAN operator experiences on first install.

The first theme is **one production nginx instead of two**. The v0.0.6 edge
topology chained a standalone edge nginx in front of the static-Web nginx
(`edge → web:4173 → SPA`). An independent audit (#660) returned verdict B:
merge the edge into the web runtime. This release implements that (#661):
`exam-web` now bakes `deploy/nginx/web.conf` into the image and serves the
static SPA and the sole public edge in one container. The standalone `nginx`
service, the `web:4173` hop, and `edge.conf` no longer exist — there is no
second nginx authority left to drift.

The second theme is **deployment documentation converged to the shipped
topology**. The zh-CN install/readme still described the pre-#585 API-only
ingress, several operator docs retained `app + db`, single-image, or
named-volume wording, and ADR-011 carried a topology sentence readable as
deployment authority. #659 closes that drift documentation-only; #664 repairs
the zh-CN semantic parity of README, INSTALL, and the development guide
against their English sources.

The third theme is **transport policy derived from the real public origin**.
An independent audit of plain-HTTP LAN deployment (#665) found a P1 defect:
production forced `Secure` on the auth cookie from `APP_MODE`, so on an
`http://` canonical origin browsers discarded the cookie and login returned
200 but never established a session. HTTPS-specific behavior (cookie
`Secure`, HSTS, CSP `upgrade-insecure-requests`) now derives from the
`PUBLIC_WEB_ORIGIN` scheme — TLS is an ingress property, never an application
mode — and the bundled proxy-trust default follows the topology instead of
collapsing every client onto the edge bridge IP.

The fourth theme is **development Compose boundaries** (#663): dev
PostgreSQL/Redis publish only on loopback, the silent `repeatable read`
server override is gone, and `pnpm db:down` destroys the disposable stack it
owns.

This remains a **pre-1.0** release.

## Problems solved

- **The production edge was a two-nginx chain with a parallel config
  authority.** PR #662 merges the edge into the web runtime: one nginx
  (`web`) serves the SPA and proxies `/api/` to `app:3000`, with request-time
  Docker DNS so app recreation cannot strand the edge. Release artifacts are
  unchanged — still one release, two coordinated images (`exam` +
  `exam-web`). The #585 security invariants are preserved verbatim: single
  public ingress, `X-Forwarded-For` **replace** (`$remote_addr`), one
  published host port (#661).
- **Plain-HTTP LAN production login was broken.** PR #665 derives cookie
  `Secure`, HSTS, and CSP `upgrade-insecure-requests` from the
  `PUBLIC_WEB_ORIGIN` scheme instead of `APP_MODE`. A stale `COOKIE_SECURE`
  value is now inert (the variable is deleted). A browser regression
  (`production-lan-http.spec.ts`) drives a real production Compose stack
  through a non-localhost HTTP origin — launchpad bootstrap, real UI login,
  cookie assertions, authenticated roundtrip — with a dedicated CI job so
  this cannot hide behind localhost secure-context behavior again.
- **The bundled topology collapsed client identity onto the edge bridge IP.**
  With the nginx edge in front of the API, an empty `TRUSTED_PROXY_CIDRS`
  made every client share one rate-limit identity and one audit IP. PR #665
  introduces `EXAM_DOCKER_SUBNET` (default `172.28.0.0/24`) as the single
  topology authority: `docker-compose.yml` derives both the `exam-net` IPAM
  subnet and the bundled `TRUSTED_PROXY_CIDRS` default from it, so the
  bundled stack works out of the box and LAN/VPN/Docker-subnet collisions are
  fixed in one place.
- **Deployment documentation described a topology that no longer shipped.**
  PR #659 syncs README.zh-CN / INSTALL.zh-CN to the nginx public-entrypoint
  shape, documents the one-release/two-image model
  (`ghcr.io/jnhu76/exam:vX.Y.Z` + `ghcr.io/jnhu76/exam-web:vX.Y.Z`),
  corrects PostgreSQL persistence wording to the bind-mounted
  `${EXAM_DATA_ROOT:-./data}/postgres` data root, removes wording that
  implied external PostgreSQL is a supported production path, and repairs
  ADR-011's stale topology sentence — documentation-only, no runtime change.
- **zh-CN docs carried machine-translation drift and invented semantics.**
  PR #664 repairs the three active zh-CN projections against their English
  sources (开卷 not 开放式, `nginx 公共入口` not `nginx 边缘`, single-tenant
  preserved as a product property, ownership mappings restored, authority
  notes absent from the English source removed).
- **Dev Compose leaked beyond the developer machine and silently differed
  from production.** PR #663 pins dev PostgreSQL/Redis publication to
  `127.0.0.1`, removes the `default_transaction_isolation='repeatable read'`
  server override (application transactions own explicit isolation), and
  makes `pnpm db:down` run `down -v` so the declared disposable lifecycle
  actually destroys its data.

## Notable changes

### Added

- `EXAM_DOCKER_SUBNET` (default `172.28.0.0/24`): the single override for
  the bundled stack's Docker bridge subnet; `docker-compose.yml` derives the
  `exam-net` IPAM subnet and the bundled `TRUSTED_PROXY_CIDRS` default from
  the same value.
- A production LAN HTTP browser regression
  (`apps/e2e/e2e/production-lan-http.spec.ts`) executed by a dedicated CI
  job against a real production Compose stack through a non-localhost HTTP
  origin.
- Deployment documentation for the one-release/two-image model and the
  bind-mounted PostgreSQL data root (#659).

### Changed

- Production topology is `web + app + db` (redis optional via
  `--profile redis`): `exam-web` serves the static SPA **and** is the sole
  public nginx edge. Only `web` publishes a host port; `/api/**` is proxied
  to `app:3000` with request-time upstream DNS. The edge config is baked
  into the image (#662).
- Transport policy derives from the canonical browser-visible origin
  (`PUBLIC_WEB_ORIGIN` scheme): `http://` origins ship auth cookies without
  `Secure` and without HSTS; `https://` origins keep `Secure`, HSTS, and CSP
  `upgrade-insecure-requests`. `APP_MODE` remains `production` for both —
  TLS is an ingress property (#665).
- The bundled `TRUSTED_PROXY_CIDRS` default is deployment-derived (from
  `EXAM_DOCKER_SUBNET`); an explicit operator value still wins. The nginx
  edge sets `X-Forwarded-Host`, replaces `X-Forwarded-For` with
  `$remote_addr`, and derives `X-Forwarded-Proto` from the ingress scheme
  (#665).
- Deployment docs converged to the current topology; zh-CN projections are
  semantically aligned with their English sources (#659, #664).
- Dev Compose: PostgreSQL/Redis publish on `127.0.0.1` only;
  `pnpm db:down` tears down the stack with `down -v` (destructive by
  contract) (#663).

### Fixed

- Plain-HTTP LAN production login: browsers discarded the forced-`Secure`
  auth cookie, so login returned 200 but the session never persisted (#665).
- Rate-limit identity and audit IP collapsed onto the edge bridge IP under
  the bundled topology with empty `TRUSTED_PROXY_CIDRS` (#665).
- HSTS and CSP `upgrade-insecure-requests` followed production mode instead
  of the actual external transport (#665).

### Removed

- The standalone production `nginx` service, the `web:4173` hop, and
  `deploy/nginx/edge.conf`; `exam-web` is the single nginx authority (#662).
- `COOKIE_SECURE`; a stale value in the environment is inert and pinned by
  test — transport policy derives from `PUBLIC_WEB_ORIGIN` (#665).
- The dev `postgres -c default_transaction_isolation='repeatable read'`
  server override (#663).

### Security

- Client-supplied forwarding headers cannot enter the application's
  trusted-proxy walk: the (now sole) nginx edge **replaces**
  `X-Forwarded-For` with `$remote_addr`; the bundled trust set names the
  stack's own bridge, never the candidate client network; trust-all CIDRs
  still fail fast (#665, preserving #585/#546).
- HTTPS behavior remains exactly HTTPS behavior: on `https://` origins the
  auth cookie keeps `Secure`, HSTS and `upgrade-insecure-requests` are
  emitted, and production script-src hardening stays mode-owned (#665).

## Verification

Release membership is defined by ancestry from the published `v0.0.6` tag
target (`b53fb608ccad12199ddb19b930e84f928ba3de6c`) through the pre-release
`master` (`b874b390f8b8fd76797929d1fbd6d570b0958ff8`). The exact range
contains 5 commits before this metadata-only release preparation.

The release-preparation change is intentionally limited to
`.release-version`, `CHANGELOG.md`, and this version-specific release
record. Its exact PR head must pass normal repository CI before merge.

After merge to `master`, `.github/workflows/release.yml` validates the
release contract on the exact merge SHA, builds **both** images (API
`runner` and web `web-runner`) before any irreversible publication step,
pushes `ghcr.io/jnhu76/exam` and `ghcr.io/jnhu76/exam-web` at `v0.0.7` plus
the `sha-*` alias (deliberately no `latest`), creates or verifies the
immutable annotated `v0.0.7` tag at that exact commit, and creates the
GitHub Release from this file. Publication is complete only after the
workflow succeeds and the tag target, the Release, and the image digests are
verified.

Evidence carried by the included PRs:

- #662: production rehearsal on source-built images — `ps` healthy
  (`app` / `db` / `web`, no nginx service), only `web` publishes a host
  port, single-ingress smoke (`/`, SPA deep link, `/api/health`,
  `/api/ready`), forged-`X-Forwarded-For` probes share one rate-limit
  bucket, `nginx -T` confirms the replace semantic.
- #663: fresh `db:up` → witness table → `db:down` → volume gone → fresh
  `db:up` → witness absent → migrate + seed succeed; listeners only on
  `127.0.0.1`; `SHOW default_transaction_isolation` → `read committed`;
  DB/concurrency coverage and canonical E2E PASS.
- #665: the transport-policy matrix is pinned by tests; the new
  `production-lan-http.spec.ts` runs against a real production Compose stack
  through a non-localhost HTTP origin (bootstrap → UI login →
  `secure:false` / `httpOnly:true` / `sameSite:"Strict"` cookie →
  authenticated `/api/auth/me` roundtrip), enforced by a dedicated CI job.

## Known limitations

- **LAN HTTP requires an isolated or appropriately trusted network.** The
  platform now supports plain-HTTP canonical origins, but HTTP carries no
  wire confidentiality or integrity; the deployment documentation states the
  LAN-isolation precondition. HTTPS remains the recommended transport where
  the deployment can carry certificates.
- **TLS activation on the baked-in edge requires a runtime-mounted override
  conf.** There is no ACME automation; the commented 443 template and the
  mount procedure are documented in INSTALL and the deployment docs.
- **No CDN, object storage, load balancer, or horizontal-scaling mechanism
  was introduced.** The built SPA remains the future extraction seam;
  #661's non-goals all hold.
- **External PostgreSQL is still not a supported operator path**; upgrades
  run against the bundled `db` service.
- **Candidate submit serialization / Exam reader lock mode is a recorded
  deferred follow-up (#668)**, intentionally outside this release.
- **Pre-1.0 baseline.** This release converges the deployment surface; it is
  not a claim that the generic-product roadmap is complete.

## Upgrade notes

`v0.0.5 → v0.0.6` → `v0.0.7` adds **no PostgreSQL migrations** and does not
change the PostgreSQL major (still `postgres:18.4-bookworm`), so no
dump/restore cycle is required beyond the mandatory pre-upgrade backup.

Operational changes to account for when upgrading from `v0.0.6`:

- **The standalone `nginx` service is gone — remove its container once.**
  The stack is now `web + app + db`; only `web` publishes the host port
  (`EXAM_PORT`, default 80). The Compose project identity is unchanged
  (`exam-prod`), but the old `exam-prod-nginx-1` container is not tracked by
  the new file: Compose reports it as an orphan and does **not** remove it
  by default, and it keeps holding the published port, so the new `web`
  container cannot bind. Bring the stack up with
  `docker compose --env-file .env.production up -d --remove-orphans` (or
  remove the orphan explicitly once). Verify afterwards that exactly one
  container publishes the port.
- **`COOKIE_SECURE` no longer exists.** A stale value is inert (pinned by
  test); remove it from `.env.production` at leisure. Whether the auth
  cookie is `Secure` is now decided by the `PUBLIC_WEB_ORIGIN` scheme.
- **Plain-HTTP LAN is a supported first-class configuration again** (on an
  isolated or appropriately trusted LAN): set `EXAM_PORT`,
  `CORS_ORIGIN`, and `PUBLIC_WEB_ORIGIN` to the browsed `http://` address;
  the login session now persists.
- **`EXAM_DOCKER_SUBNET` is the one topology override.** If `172.28.0.0/24`
  collides with your LAN, VPN, or another Docker network, set a free RFC1918
  subnet once — the bridge subnet and the bundled proxy-trust default move
  together. If you previously hand-derived `TRUSTED_PROXY_CIDRS` from the
  bridge subnet after the first `up`, you can delete that line; an explicit
  override (external proxy topologies) still wins.
- **HTTPS activation changed shape.** The edge config is baked into the
  `exam-web` image; enabling TLS requires a runtime-mounted overriding conf
  (documented in INSTALL and the deployment docs), not an edit to
  `edge.conf` on disk — which no longer exists.

Version skipping remains supported by default: migrations are
forward-append-only and the journal applies any backlog in order. There is
no mandatory intermediate version for this release.
