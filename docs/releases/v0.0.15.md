# Exam v0.0.15

## Why this release exists

`v0.0.15` is a web front-end correctness-and-accessibility remediation
release. Its substance comes from the senior-frontend skill audit of
`apps/web` ([#971](https://github.com/jnhu76/exam/issues/971), baseline
`d3e74dd4`, evidence archived in `docs/archive/audits/971-frontend-senior-skill/`
and the do-not-merge record
[#972](https://github.com/jnhu76/exam/pull/972)), executed as six fix
waves (W1–W6). The release closes all five P1 findings — the candidate
answer-loss window (F-01), the dead permission inspector (F-03), the
mouse-only row activation (F-02), the screen-reader-invisible permission
matrix state (F-04) and the hand-written combobox with a second debounce
authority (F-05) — plus the P2 batch routed into the waves (F-06, F-07,
F-08, F-10, F-11, F-20) and the wave-review findings the fixes surfaced
(R6, R7, R8, R9, S5). It also carries the ADR-028 proposal (#964 W0,
PR [#970](https://github.com/jnhu76/exam/pull/970)) as documentation-only
groundwork for the observability campaign; the OTel implementation waves
are separate open PRs and are not part of this release.

The release contains **no database migration, no environment-variable
change, and no wire contract change** (`packages/contracts` is
untouched). The only dependency addition is web-internal (`cmdk`,
backing the new `command.tsx` combobox primitive).

## Problems solved

1. **Leaving a page could silently drop a candidate's typed answer (#971
   F-01/F-08/R6, PR [#990](https://github.com/jnhu76/exam/pull/990),
   issue #981).** The 1.5s debounced answer save was dropped on unmount:
   leaving within the window permanently lost keystrokes with no
   indication. Exam-controlled exits now hold navigation until in-flight
   answer saves are server-confirmed, only accepted saves are
   acknowledged (a rejected save surfaces instead of being counted as
   saved), and the save chip announces its state transitions via
   `role="status"` `aria-live="polite"` so screen-reader users are no
   longer silent during saves.

2. **The permission registry's user permission inspector was a dead
   feature (#971 F-03, PR [#986](https://github.com/jnhu76/exam/pull/986),
   W1).** The staff directory requested a non-existent API route and
   silently swallowed the 404 into an empty list — browser verification
   caught what static review missed. The page now consumes the real
   `GET /api/users` pagination contract, retries a failed directory page
   instead of discarding it, and keeps the selection coherent when a
   retry lands.

3. **A family of keyboard and screen-reader blockers on tables and the
   permission matrix (#971 F-02/F-04/F-06/F-07 + matrix overlap, PR
   [#991](https://github.com/jnhu76/exam/pull/991), issue #984, W5).**
   Row activation was a mouse-only `<tr onClick>` with no Tab stop; the
   matrix's only "granted" signal was `aria-hidden`; the focus ring
   measured ≈1.2–1.8:1 against the WCAG 1.4.11 3:1 floor; every row's
   action buttons shared one name ("编辑用户" ×17), so screen-reader row
   navigation heard duplicates. Rows are now real Tab-reachable stops,
   the granted state is perceivable by assistive technology, the focus
   ring meets the 3:1 non-text contrast floor, row actions announce
   which row they act on, and the matrix key column scrolls
   independently below `sm` so keys stay visible next to their rows.

4. **`CourseSearchSelect` ran two query authorities side by side (#971
   F-05, PRs [#989](https://github.com/jnhu76/exam/pull/989)/
   [#992](https://github.com/jnhu76/exam/pull/992), issue #985, W6).**
   The hand-written combobox carried a second debounce timer — a
   governance double-authority the project's own rules forbid — with
   Enter able to commit a stale query mid-flight. It is migrated to the
   cmdk combobox primitive with one query owner: a pending debounced
   search is cancelled on course-scope change, and Enter stays inert
   while a query is pending so no stale commit can win.

5. **A stale-response family let superseded reads overwrite staff and
   candidate surfaces (#971 F-10/F-11/S5/R7/R8, PR
   [#987](https://github.com/jnhu76/exam/pull/987), W4).** Grading queue
   pagination/refresh, grading detail's authoritative re-read after a
   score POST (a slow earlier GET could visually revert an already
   committed later grade), the candidate result snapshot (now bound to
   `attemptId`), the proctor status poll (now owning its `examId` with
   single-flight ticks), and system diagnostics per-stream reads all
   discard superseded responses instead of letting the last response to
   land win; a committed grade is locked before its refresh can be
   superseded.

6. **Exam scheduling mixed time-zone authorities across create, edit and
   confirm (#971 F-20/R9, PR [#988](https://github.com/jnhu76/exam/pull/988),
   W3).** `datetime-local` wall-clock strings round-tripped through the
   browser time zone while the confirm preview rendered the same string
   in the organization zone — when the two differ, the confirmed moment
   was not the stored moment. The wall-clock ↔ instant conversion now
   goes through the product time-boundary seam, resolved schedule
   instants are the wizard's wire authority, the edit page preserves
   stored instants and fills the organization wall clock, and
   organization settings keep one live owner per identity.

7. **ADR-028 (OpenTelemetry technical telemetry standard) is proposed
   (#964 W0, PR [#970](https://github.com/jnhu76/exam/pull/970)) —
   proposal-stage documentation defining telemetry boundaries and
   compatibility evidence for the observability campaign. No runtime
   telemetry changes in this release.**

## Notable changes

### Changed

- Exam scheduling speaks one time-zone contract across the create
  wizard, edit page and confirm step (#971 F-20/R9, PR #988); resolved
  schedule instants are the wizard wire authority and the edit page
  preserves stored instants.
- `CourseSearchSelect` runs on the cmdk combobox primitive with one
  query owner (#971 F-05/#985, PRs #989/#992).
- ADR-028 (OpenTelemetry technical telemetry standard) proposed as
  documentation (#964 W0, PR #970) — no runtime telemetry change.

### Fixed

- Leaving a page can no longer silently drop a candidate's typed answer;
  controlled exits wait for server-confirmed saves and the save chip is
  announced to assistive technology (#971 F-01/F-08/R6, PR #990).
- The permission registry's user permission inspector works again on the
  real staff-directory pagination contract (#971 F-03, PR #986).
- The stale-response family on grading, proctor, diagnostics and
  candidate-result surfaces discards superseded reads; a committed grade
  is locked before its refresh can supersede it (#971
  F-10/F-11/S5/R7/R8, PR #987).
- Table rows are keyboard-operable, permission-matrix state is
  AT-perceivable, the focus ring meets the 3:1 non-text contrast floor,
  row actions announce their row, and the matrix key column scrolls
  independently below `sm` (#971 F-02/F-04/F-06/F-07 + overlap, PR #991).

### Internal / infrastructure

- Web-internal dependency addition `cmdk` with the new
  `apps/web/src/components/ui/command.tsx` primitive (PR #992);
  `packages/contracts`, database schema and environment variables are
  untouched in this range.

## Upgrade notes

- **Read §2 of
  [`docs/deployment/upgrade-and-uninstall.md`](../deployment/upgrade-and-uninstall.md)
  first.** The upgrade is the existing paired-image procedure: deploy
  `ghcr.io/jnhu76/exam:v0.0.15` **and** `ghcr.io/jnhu76/exam-web:v0.0.15`
  together (`init-production-env` rewrites `EXAM_IMAGE`/`EXAM_WEB_IMAGE`
  from `.release-version`; no `latest` tag is published). Take the
  mandatory pre-upgrade backup (runbook §15) — it is also the rollback
  material (§2.5).
- **No database migration.** The schema is unchanged from v0.0.14; the
  entrypoint's migration step is a no-op on an up-to-date deployment.
- **No environment or configuration change is required.**
- **Behavioral notes.**
  - Exam-controlled navigation out of the taking page now waits for
    server-confirmed answer saves; in the rare case a save is rejected,
    the candidate sees the failure surfaced instead of a silent loss.
  - Schedule instants already stored are unchanged; the fix corrects the
    wall-clock ↔ instant conversion on create/edit/confirm, so
    deployments where the organization time zone differs from operators'
    browser time zones will see the confirm preview match what is
    actually stored and listed.
  - Table rows and the permission matrix are now keyboard-operable and
    announced to assistive technology; focus rings are more visible by
    design (3:1 contrast floor).
- **Rollback (§2.5).** No migrations are involved: rollback = redeploy
  the previous image pair (plus the standard pre-upgrade backup
  discipline). Beware the canonical-pin auto-revert on the next
  `init-production-env` run — pin by digest or edit after (§2.5).
- **Version skipping** stays supported by the migration journal replaying
  any backlog in order.
