# Exam v0.0.3

## Why this release exists

`v0.0.3` is the first release that turns Exam from a single-role
administration/grading platform into a multi-role, content-rich exam
baseline. Between `v0.0.2` and `v0.0.3` the product gained scoped
Teacher@Course and Grader@Exam authority, a staff identity lifecycle
(invitation + email password reset), a permission registry with
audit-log search/export, Plain/Rich (WYSIWYG) question content, and two
new exam timing modes (`deadline`, `untimed`). Deployment also converged:
email delivery now runs in-process (the dedicated email-worker service is
gone) behind an explicit shutdown-budget contract, and configuration is
unified behind a semantic settings model. A synchronized-timing kernel
(Phase B of the timing-mode roadmap) was merged as latent preparation
only — it changes no product-visible behavior yet.

## Problems solved

- **Authorization was org-wide or nothing.** Teachers and Graders could
  see and act on everything. The scoped authority models bind each role
  to explicitly assigned courses/exams (`capability × assignment`),
  filter every list in SQL before pagination, and fold out-of-scope
  probes into the canonical 404 (anti-enumeration) — revocation is
  effective on the next request (#286, #296).
- **Operators had no staff self-serve identity path.** Staff invitation
  with role choice, email password reset, and account lifecycle now work
  end to end (#297).
- **Permission and audit data existed but was not visible.** A
  permission registry and audit-log search/export (API + UI) expose
  effective authority and actor/target-filterable audit history (#298).
- **Questions were plain text only.** A Plain/Rich content model with
  lazy Tiptap/KaTeX supports math, tables, and code in authoring, taking,
  grading, and results — with rich content frozen into exam snapshots so
  later edits cannot mutate live exams (#301).
- **All exams were time-boxed identically.** `deadline` (no per-person
  countdown, single closing time) and `untimed` (no personal limit, no
  close) modes are now authorable and takable, with null-safe deadline
  authority in the engine (#291 Phase A, #387/#388/#390).
- **Email delivery had a second process to run and a fragile lifecycle.**
  Delivery now runs in-process with an explicit shutdown budget, fail-
  closed backup evidence, and Compose env parity so documented SMTP/TLS/
  timeout settings actually reach the container (#320, #351, #368).
- **An attempt could start with no reachable manual submit.** Attempts
  whose parameters leave no window to satisfy the minimum manual-submit
  duration are now rejected at start (#395).
- **Test/evidence debt was growing.** The anti-decay campaign removed
  roughly 1,900 net lines of duplicated, visual-only, or over-minimized
  recovery/incident and rich-content test evidence, retired
  `rebuild-all.sh`, centralized governed UI scan-root authority, and
  wired every verifier script to a gate (#357/#361/#362, #378/#382,
  #379/#384, #380/#385, #383/#386).

## Notable changes

### Added

- Scoped Teacher@Course authority with persisted assignment carrier,
  Admin assignment API + UsersPage dialog, and SQL-side LIST scope
  filtering (#286).
- Scoped Grader@Exam authority with persisted assignment carrier, Admin
  assignment API + UsersPage dialog, and grading-queue scope filtering
  (#296).
- Staff invitation, email password reset, and account lifecycle (#297).
- Permission registry and audit-log search/export (API + UI) (#298).
- Plain/Rich content model and WYSIWYG V1: ContentDocumentV1 kernel,
  lazy Tiptap editor, lazy KaTeX math seam, rich rendering across
  authoring/taking/grading/results, snapshot-frozen rich content (#301).
- `deadline` and `untimed` exam timing modes: nullable duration/close-at,
  per-profile `timing_mode`, author-and-take support (#291 Phase A).
- Synchronized-timing kernel preparation: `exams.sync_started_at` and an
  engine timer kernel — latent, not product-activated (#291 Phase B1).

### Changed

- Email delivery runs in-process; the `email-worker` Compose service is
  gone; delivery has an explicit shutdown-budget contract (#320, #351).
- Email SMTP/TLS/timeout env keys now reach the app container with
  default-equal fallbacks, guarded by a topology parity oracle (#368).
- Application configuration unified behind a semantic settings model
  (#372).
- Governed business-UI scan roots centralized; eslint scope covers
  notifications/features; verifier scripts gate-wired (#379/#380/#383/
  #384/#385/#386).
- `run-wsl` binds `PUBLIC_WEB_ORIGIN` per API shard (#364/#365).
- Docker E2E runner cleanup failures fail loud (#375/#376).

### Fixed

- Attempt starts without a reachable manual-submit window are rejected
  (#395).
- Admin exam detail page handles nullable timing modes correctly (#389).
- Deadline authority is null-safe for no-deadline exams (#387).
- Invitation concurrency coverage accepts both legal interleavings (#381).
- Queue-participant DB test hook budgets completed (Guard 5) (#373).

### Removed

- Dedicated email-worker service (in-process delivery) (#320).
- `rebuild-all.sh` (hand-mirrored build order) (#378/#382).
- Unused attempt time-extend permission (#363) and obsolete shadow
  permission mode (#366).
- Roughly 1,900 lines of duplicated/visual/over-minimized recovery,
  incident, and rich-content test evidence (#357/#359/#361/#362).

### Deployment / operations

- Compose topology is now `app` + `db` + `redis`; no separate email
  worker to run or monitor. `up -d` recreates `app` with the new image;
  `db` data is untouched.
- Email/SMTP configuration: seven previously-ignored variables are now
  forwarded (defaults match runtime defaults), so documented settings
  behave as documented.

### Internal / infrastructure

- Semantic settings model replaces profile env contracts as the gate
  authority (#372).
- Anti-decay campaign: recovery evidence minimization, verifier
  meta-guard, single UI scan-root authority, `rebuild-all.sh` retired
  (#361/#362/#382/#384/#385/#386).

## Known limitations

- **`timed_sync` is not product-activated.** The synchronized-timing
  kernel (`sync_started_at`, engine timer kernel) is merged, but the
  `timed_sync` mode cannot be authored or taken: profile `timing_mode`
  CHECK excludes it, there is no sync-start command, and no runtime
  admits it. Admission semantics are frozen by ADR/SPEC (#291 Phase B0);
  activation is Phase B2, tracked under #291.
- **No durable admission queue.** `requireQueue` remains a legacy
  in-memory admission gate; there is no durable admission queue
  (#394 open).
- **Single-node deployment only.** Multi-instance support is not
  provided in this release.
- **Single-tenant.** One deployment is one organization; `organizationId`
  is an internal data boundary, not a multi-tenant product capability.
- **WYSIWYG asset upload is not included.** The rich content model is
  asset-ready in schema/limits but images/attachments require an Asset
  authority that is not yet implemented (ADR-019).
- **Published images are linux/amd64 only**; other architectures use the
  documented source-build path.
- **Pre-1.0 development baseline**; the generic product roadmap continues
  under Issue #333.

## Upgrade notes

`v0.0.2 → v0.0.3` introduces six forward-only migrations (0036–0041):
`teacher_course_assignments`, `grader_exam_assignments`,
`identity_lifecycle_tokens`, `question_rich_content_slots`,
`phase_a_timing_modes` (nullable duration/close-at + profile
`timing_mode`), and `phase_b_sync_started_at` (nullable column, no
backfill). They are applied automatically by the entrypoint migration
journal on app start, in order, idempotently; no manual SQL or backfill
is required.

No special operator action is required beyond the standard pre-upgrade
backup: `git pull` → `node scripts/generate-env.mjs` (re-pin
`EXAM_IMAGE`) → `docker compose --env-file .env.deploy pull` →
`up -d`. The removed `email-worker` service means the stack now recreates
`app` (and leaves `db` untouched); email delivery is handled in-process.
The seven newly-forwarded email environment keys all have defaults equal
to the runtime defaults, so existing `.env.deploy` files keep working
unchanged. Rollback follows the documented forward-only contract in
`docs/deployment/upgrade-and-uninstall.md` (restore the pre-upgrade
backup + redeploy the previous image tag).
