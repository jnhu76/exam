# Exam v0.0.11

## Why this release exists

`v0.0.11` is a post-`v0.0.10` correctness, truthfulness, and architecture-honesty
release built around three cores.

First, it fixes real correctness defects: JSON-like fill-blank standard
answers (`"42"`, `"true"`, `"1e3"`, …) were silently type-drifted by a double
JSONB parse on read and then mis-graded (#845); the Admin dashboard reported a
hardcoded `participantCount: 0` (#833); and three sites fabricated empty
identities or `0%/0ms` telemetry instead of failing closed on unresolvable
data (#836, #837).

Second, it removes the backup-evidence subsystem under
[ADR-023](../adr/ADR-023-remove-backup-evidence-subsystem.md) (#739): the
five-table attestation ledger shared the failure domain of the database it
described and could render stale-green compliance that outlived its artifacts.
Exam keeps health/diagnostics; backup execution, verification, and operational
evidence become explicitly host-operator obligations. The removal is a
**breaking API/RBAC change** carried by forward-only migration `0045` with an
evidence-preservation gate (see Upgrade notes).

Third, it lands the UX-R1 campaign implementing the independent UI audit
decisions (#834): retake becomes reachable once a final score exists, the
candidate result page gains a shared question-type dictionary and a mobile
per-question view, the save indicator and offline banners stop overpromising,
grading resolves grader display names with a next-pending action, candidate
touch targets reach 44px with unified passing-requirement copy, and rich
content stops clipping document-level overflow while exposing an accessible
MathML projection of formulas (#847).

The release is based on the actual ancestry `v0.0.10`
(`5d005a58a51ff3f908f620d70791ed29fe114e37`) → preparation base `master`
(`9e87f69ebe6440d2335b1c7260b6ed467ef5c5ff`): 62 commits containing 24 merged
PRs (#809–#811, #814–#816, #818, #822, #823, #825, #826, #829, #830, #832,
#835, #838–#844, #846, #848) plus one direct docs-only push (`c5814def`,
OBS flake-evidence record). The release-preparation merge adds only the three
release-authority files.

## Problems solved

1. **JSON-like fill-blank answers were mis-graded (#845).** postgres.js
   already decodes JSONB columns; a second `JSON.parse` on a decoded scalar
   string turned the authored standard answer `"42"` into the number `42`
   (and `"true"` into a boolean, `"1e3"` into a number, …), which the
   string-only exact matcher then failed. PR #846 (merge `31011ea1`) pins the
   question standard-answer column as a decoded-JSONB custom type that
   preserves the authored string end-to-end, with a nine-case regression
   through the real repository and domain grading.

2. **The dashboard lied about participation and telemetry (#833, #836).**
   `getRecentExams` hardcoded `participantCount: 0` while the exam list
   reported real counts; PR #835 replaces the stub with a real batched
   enrollment count and pins the semantics by test. The system diagnostics
   page rendered missing health as `0%/0ms`; PR #838 renders an explicit
   no-data state instead.

3. **Broken references fabricated empty identities (#837).** Three sites
   (recovery queue, candidate routes) returned empty-name/`isActive` stubs
   when a user link could not be resolved; PR #838 makes them fail closed
   with explicit error states instead of disguising corruption as absence.

4. **Retake was unreachable after a final score existed (#834 R1-F1/F6).**
   The exam-list state machine returned `graded → view_result` for every
   candidate with a final score, so candidates who failed and still had
   retake eligibility — and unlimited-retake or pass-then-stop candidates —
   could never start a new attempt from the list, even though the start
   command admitted them. PR #839 routes the `graded` branch through the
   same retake authority as the start command (`isCandidateRetakeDeferred`,
   EXSEM-018 visibility authority), keeps the published result viewable on
   the card, and keys attempts copy on the real `retakePolicy` instead of a
   sentinel number (`unlimited` renders as 不限次数, not 已考 0/99次).

5. **The candidate result page was unreadable on phones and dishonest in
   columns (#834).** PR #840 renders question types through a shared
   dictionary, drops the contentless correct-answer column, clamps long
   answers behind a keyboard-operable disclosure, and adds a mobile
   per-question view.

6. **Save/submit feedback overpromised (#834).** PR #841 maps the idle save
   chip to the actually-synced steady state (skipped saves surface an error,
   not a success), splits the offline banners' promises between connection
   and save state, and weights the submit-dialog facts by risk instead of
   equal lines.

7. **Grading lost the grader's name and the queue's thread (#834).** PR #842
   resolves the grader display name in grading details (API resolves
   `gradedByName`), remounts the grading detail page per attempt id, and
   adds a continue-with-next-pending action.

8. **Candidate touch targets were below mobile minimums and passing-requirement
   copy diverged (#834).** PR #843 raises candidate exam card touch targets
   to 44px on mobile and unifies the passing-requirement copy across pages.

9. **Proctor/dashboard clarity (#834).** PR #844 makes the force-submit
   confirm button state the exact action, relabels the dashboard today stat
   as an attempt count with pinned counting semantics, and checks the
   monitoring empty state.

10. **Rich content clipped at the document level and formulas had no
    accessible representation (#847, #699 lineage).** PR #848 makes overflow
    local (a `ContentScrollViewport` contract: un-clamped content stays
    wrapped and scrollable where it lives, nothing clips the page), keeps
    un-clamped answers re-measurable, and switches KaTeX output to
    `htmlAndMathml` so the visually-hidden MathML tree is the screen-reader
    copy of every formula. Verified at DOM/CDP level by four new E2E journeys
    and ~50 component tests; see Known limitations for what is **not**
    claimed.

11. **The backup-evidence subsystem produced stale-green confidence
    (#739/ADR-023).** The #739 audit found a closed orphan loop: no
    automated producer, no operational consumer, free-text verification, and
    a ledger sharing the failure domain of the database it attested about —
    a previously verified SUCCESS record could outlive its artifact and keep
    rendering green. The owner resolved REMOVE. PRs #814 (ADR), #815
    (product code), #816 (migration + operator tooling) and #818 (safety-gate
    closeout) executed the removal; §Upgrade notes covers the gate.

12. **Governance claims drifted from reality (#821, #824).** The #821 audit
    found docs claiming gates that did not run; PRs #822/#823 repaired the
    false gate claims and dependency facts, PR #825 made forbidden workspace
    runtime dependencies machine-enforced from a single authority table
    (`config/architecture-policy.mjs`), and PR #826 consolidated the agent
    instruction contract. Documentation now states the Standard product's
    real capabilities (PR #829) with a bounded repo-only VitePress pilot
    (PRs #830, #832).

## Notable changes

### Added

- `retakePolicy` (`max_attempts` | `unlimited` | `pass_then_stop`) is now
  projected in the candidate exam list and detail responses, so clients key
  attempts copy on the authored policy instead of inferring from a sentinel
  (#834, PR #839).
- Grading details now resolve `gradedByName` for the grading actor, and the
  grading session offers a continue-with-next-pending action (PR #842).
- Operator tooling for the ADR-023 evidence-preservation gate:
  `scripts/verify-evidence-preservation.sh` (manifest capture/compare,
  fail-closed) with its self-test, backing the §2.7 upgrade workflow
  (PR #816).
- A bounded, repo-only VitePress documentation pilot (`pnpm docs:build` as a
  CI check; no publication target) and truthful Standard product
  documentation (PRs #829, #830, #832).

### Changed

- Retake reachability: candidates with a final score who still have retake
  eligibility (failed with attempts remaining, unlimited, or
  pass-then-stop-not-yet-passed) can start a new attempt from the exam list;
  the published result stays viewable on the card (#834, PR #839).
- The dashboard "today" stat is labeled as an attempt count, and its
  counting semantics are pinned by test (PR #844).
- The save indicator's idle state means actually-synced; skipped saves
  surface an error; offline banners separate connection loss from save
  state; the submit dialog weights facts by risk (PR #841).
- Formula rendering emits `htmlAndMathml`: the visual HTML is
  `aria-hidden`, and the visually-hidden MathML tree is the accessible
  representation (PR #848).

### Fixed

- Fill-blank questions with JSON-like scalar standard answers are graded
  against the authored string, not a re-parsed value (#845, PR #846).
- Dashboard recent exams report real enrollment counts instead of a
  hardcoded 0 (#833, PR #835).
- Missing health telemetry renders an explicit no-data state instead of
  0%/0ms (#836), and unresolvable user references fail closed instead of
  rendering empty identities (#837) (PR #838).
- Candidate result page readability fixes: shared question-type dictionary,
  removal of the contentless correct-answer column, keyboard-operable
  disclosure for long answers, mobile per-question view (PR #840).
- Candidate exam card touch targets meet 44px on mobile; passing-requirement
  copy is unified across pages (PR #843).
- Rich content no longer clips at the document level: overflow is local to
  the content viewport, un-clamped answers stay wrapped, and re-measure is
  reliable after resize (#847, PR #848).

### Removed

**Breaking** — backup-evidence subsystem (ADR-023, #739):

- API endpoints `GET /api/system/backups`, `GET /api/system/restore-readiness`,
  `GET /api/system/retention-readiness`, `GET /api/system/ops-policy` and
  `PUT /api/system/ops-policy` (PR #815).
- Permission keys `system.backup.view`, `system.restore_readiness.view`,
  `system.ops.policy.view`, `system.ops.policy.manage` from the catalog and
  every preset; the Maintainer preset is re-baselined from five to exactly
  two read capabilities: `system.health.view` + `system.diagnostics.view`
  (PR #815).
- The backup-evidence CLI (`backup-evidence.ts`), its repositories,
  contracts DTOs, and the OperationsPage backup/ops-policy sections
  (PR #815).
- Database tables `backup_runs`, `backup_run_events`, `restore_drill_runs`,
  `retention_runs`, `backup_operational_policy` by forward-only migration
  `0045_drop_backup_evidence_tables` with a pre-drop evidence-preservation
  gate (PR #816). Applied migrations 0031–0034 remain untouched history.

Backup execution, verification, restore drills, and operational evidence are
host-operator obligations (`scripts/db-backup.sh`, runbook §15/§17);
`/system/health` and `/system/diagnostics` are unchanged.

## Known limitations

- **Math accessibility is DOM-level, not human-AT-verified.** KaTeX now
  emits a MathML tree that automated tests verify is present and is the
  single accessible copy, but **no human screen-reader acceptance (NVDA,
  VoiceOver, or equivalent) has been performed**. True 200% browser zoom is
  unverified (720px reflow is the verified proxy). A P3 residual remains:
  an un-clamped answer does not re-clamp after later font/viewport growth
  (content stays visible; tracked as follow-up in #847's thread).
- **Answer-durability findings are research, not product guarantees.** The
  #817 fault-injection campaign (closed; evidence in the issue threads, no
  product code changed) measured that browser-side termination inside the
  pre-debounce save window loses unsent input (D7), and that dump/restore
  has a measured recovery-point gap (D6, experimental). No zero-loss SLA,
  browser offline draft persistence, or PITR capability is claimed or
  shipped; the research continues in open #813/#827/#828.
- **Removed surfaces have no compat shim.** Scripts or integrations calling
  the five removed `/system/*` endpoints, or relying on the Maintainer's
  three removed views, break at 404/403 on upgrade (see Upgrade notes).
- **Documentation portal is repo-only.** The VitePress pilot builds in CI;
  no GitHub Pages, hosting, domain, or telemetry exists (#751 stays open).
- **#678 remains Phase 1 only** (closed Standard capability catalog,
  fail-closed resolver, read-only `public-config` projection shipped in
  v0.0.10). Phase 2 write guards, the Minimal preset, and persisted
  deployment configuration are not implemented.
- High-assurance Controlled/Strict profiles, `timed_sync`, multi-tenant
  platform features, and site-specific production capacity/TLS/restore
  certification remain future work (roadmap and implementation-status
  documents).
- The historical flake registry (`docs/standards/test-flakes.md`) carries
  unresolved QA-process debt classes; both release-relevant CI lanes are
  green on their heads.

## Upgrade notes

- **Read §2 of
  [`docs/deployment/upgrade-and-uninstall.md`](../deployment/upgrade-and-uninstall.md)
  first.** The upgrade itself is the existing paired-image procedure:
  deploy `ghcr.io/jnhu76/exam:v0.0.11` **and**
  `ghcr.io/jnhu76/exam-web:v0.0.11` together (`init-production-env` rewrites
  `EXAM_IMAGE`/`EXAM_WEB_IMAGE` from `.release-version`; no `latest` tag is
  published). Take the mandatory pre-upgrade backup (runbook §15) — it is
  also the rollback material (§2.5).
- **Migration 0045 / evidence-preservation gate (§2.7).** Deployments whose
  five backup-evidence tables are **empty** (the default; the feature had no
  automated producer) migrate silently. Deployments holding **rows** will
  **intentionally fail to start**: the migration aborts before any DROP,
  rolls back completely, records no journal entry, and leaves tables and
  rows intact, with the gate error in the `app` container logs. That abort
  is a data-safety gate, not a tooling failure — an operator who sees it has
  skipped the §2.7 workflow (owner disposition → quiesce → full-database
  dump → manifest capture/compare via
  `scripts/verify-evidence-preservation.sh` → owner-authorized cleanup →
  re-run upgrade). Never TRUNCATE production tables to make the upgrade
  pass, and never skip 0045. **A hands-free upgrade is only guaranteed for
  empty-table deployments.**
- **Rollback (§2.5).** Migrations are forward-only: rollback = restore the
  pre-upgrade database backup **plus** redeploy the previous image pair.
  If the upgrade was blocked by the gate (0045 not applied, no journal
  entry), simply restarting with the previous release is sufficient. After
  0045 has applied, there is no in-place rollback, and old (≤ v0.0.10)
  images must never run against the migrated database. Beware the
  canonical-pin auto-revert on the next `init-production-env` run — pin by
  digest or edit after (§2.5).
- **API/RBAC compatibility.** The five removed `/system/*` endpoints now
  return 404; the four removed permission keys no longer resolve. Role
  presets are code-derived, so existing Maintainer users automatically
  receive the two-capability set on upgrade — no operator action or data
  migration. Third-party clients that strictly validate the candidate exam
  list/detail responses must accept the new `retakePolicy` field, and
  grading-details consumers may receive `gradedByName` (nullable).
- **Version skipping** remains supported by default (§2.4): the migration
  journal replays any backlog in order; a jump such as `v0.0.9 → v0.0.11`
  is a supported path and still passes through 0045's gate.
- **No configuration changes**: no new or changed environment variables, no
  Compose file changes, no new setup steps beyond the gate workflow above.
  Every step of §2.7 (inventory, disposition, dump, manifests, authorized
  cleanup) is a **deployment-owner action** performed by the operator in
  the deployment's own records, never in this repository.
