# Exam v0.0.14

## Why this release exists

`v0.0.14` is a correctness-hardening release. Its substance comes from two
adjacent audit tracks: the Temporal Authority & Exam Capability Boundary
Audit ([#961](https://github.com/jnhu76/exam/issues/961), base `77f86a30`)
and the stale-navigation race family it surfaced on the admin front-end
([#953](https://github.com/jnhu76/exam/issues/953),
[#956](https://github.com/jnhu76/exam/issues/956),
[#958](https://github.com/jnhu76/exam/issues/958)). The audit found no P0;
the findings it did find were fixed with per-fix counterfactual evidence:
three P1 last-settled-response races on admin pages (H-01/H-02/H-03), the
H-07 entry-ownership family on the candidate start path, the H-08
start-vs-close serialization gap — upgraded from a static `EVIDENCE_GAP`
to a real-PostgreSQL-reproducible correctness defect during
[PR #963](https://github.com/jnhu76/exam/pull/963) — the H-04 temporal
timestamp semantics gap, the R-02 timer-rounding premature-submit loss
path, and the R-04 heartbeat rewind path. Two CI fixture defects
([#960](https://github.com/jnhu76/exam/issues/960) deadlock blame, the
#953-family debounce timing) are also fixed so the release evidence itself
is trustworthy.

The release contains **no database migration, no environment-variable
change, and no wire contract change** (`packages/contracts` is untouched;
the new `deadline_auto_submit_deferred` telemetry flows through the
existing `exam_telemetry` kind).

## Problems solved

1. **Attempt start could interleave with exam close/cancel into
   non-serializable final states (#961 H-08, PR #963).** The start path read
   the Exam row without a lock and never re-checked it; the admin
   transition's unresolved-attempt guard ran on a REPEATABLE READ snapshot.
   Two schedules were reproduced deterministically on real PostgreSQL with
   two physical connections (7 RED → 10 GREEN): start creating an attempt on
   an already-closed exam (untimed mode: an attempt with no deadline at
   all), and close succeeding while blocked behind an in-flight start
   because its snapshot could not see the uncommitted attempt. The fix
   takes the Exam row write lock and re-checks the OPEN gates on the locked
   authoritative snapshot before the create decision, and moves the admin
   transition executor to READ COMMITTED so statements after a lock wait
   observe what was committed while waiting.

2. **Admin pages accepted any last-settled response (#961 H-01/H-02/H-03,
   PRs #959/#965).** ScoreListPage, ExamMonitoringPage (timeline + 15s
   attempt polling + visibility refresh) and PermissionRegistryPage had no
   request-ownership guard: whichever response landed last won the page
   state, so a superseded response could render rows, error states,
   timelines or effective authorities that the current selection or URL no
   longer names. Each data source now carries a latest-request generation
   guard following the established QuestionPage/ScoreListPage pattern.

3. **Debounced text commits could rewrite the history entry the user
   navigated to (#953, PR #955; #956, PR #957).** The cancel chain for the
   search/filter debounce is render/effect-carried; an external navigation
   (Back/Forward/link) commits on the history instance synchronously, and
   a debounce deadline expiring inside that gap rewrote the destination
   entry and fired a query conditioned on the departed draft. The commit
   boundary now validates the live history entry key — the only channel
   that reflects a committed navigation synchronously — and rejects the
   stale draft (+1 ref, +0 effects per page).

4. **StartExamPage could act after the page was no longer valid (#961
   H-07, PR #965).** The queue-poll loop checked cancellation only at sleep
   boundaries: after leaving the page (or changing the route's `examId`),
   an in-flight join could still POST the start command and navigate the
   user to the old exam's attempt, and a double-click could launch two
   competing queue/start flows. Entry is now a single-flight operation with
   per-operation identity, re-checked at every await boundary; the route
   detail view also guards by route identity (H-07 AttemptDetailPage item).

5. **Client timer display rounding could trigger a premature irreversible
   submit (#961 R-02, PR #967).** `ExamTimer` derived the expiry decision
   from the floored display seconds (`00:00` up to 999ms early) and the
   page submitted directly; a client clock forward-jump widened the loss to
   arbitrary size. Display and expiry are now separated (un-rounded
   server-adjusted time), and the deadline episode submits only after a
   server-side frozen-snapshot verification (`reconcileAuthoritativeAttempt`)
   — otherwise it defers with `deadline_auto_submit_deferred` telemetry and
   re-arms. The server deadline scanner remains the authoritative freezing
   path.

6. **`submittedAt` carried three unmarked semantics (#961 H-04, PR #966).**
   Scanner terminalization recorded the scan tick while lazy on-read
   reconciliation recorded the canonical effective deadline; every
   downstream consumer (scores, CSV export, admin/grading ordering) read
   the mixed column. Scanner terminalization now records the effective
   deadline (one semantics), the submission effective time is separated
   from the terminalization observation, and terminalization processing
   time is sampled per candidate instead of once per scan round.

7. **A late-arriving older heartbeat could rewind activity (#961 R-04, PR
   #966).** `last_activity_at` writes had no monotonic guard, so an older
   heartbeat landing late could pull the activity time backwards and feed
   the disruption staleness check a false inactivity. The write is now
   monotonic.

8. **Temporal documentation drift (#961 H-05 partial, PRs #966/#968).**
   ADR-006, `exam-runtime` and `state-and-authority` were aligned with the
   as-built temporal semantics, including the per-candidate scanner
   execution-time wording introduced by the same release.

9. **Two CI fixture defects undermined evidence trust.** The real-PG 40P01
   deadlock coverage fixture assumed first-queuer blame, which PostgreSQL
   does not guarantee (at most one deadlock check per lock wait, never
   re-armed) — the fixture is now victim-agnostic and the product retry
   logic was proven unaffected (#960, PR #962). The A12(c) Back-debounce
   and hook external-reset tests were load-dependent by construction and
   one never exercised the reset it pinned; both are now deterministic
   under fake timers and fail when their rule is mutation-removed (#953
   test defects, PR #954).

## Notable changes

### Changed

- Temporal timestamp semantics (#961 H-04/R-01/R-04, PR #966): scanner
  terminalization records `submittedAt` at the canonical effective deadline
  (same semantics as lazy on-read reconciliation) instead of the scan tick;
  the submission effective time is separated from the terminalization
  observation; terminalization processing time is sampled per candidate
  rather than once per scan round (with detected-ordering clamping); the
  heartbeat `last_activity_at` write is monotonic.
- ADR-006, `docs/architecture/exam-runtime.md` and
  `docs/architecture/exam-system/state-and-authority.md` aligned with the
  as-built temporal semantics, including the scanner execution-time wording
  (#961 H-05 partial, PRs #966/#968).

### Fixed

- Attempt start is serialized against exam close/cancel (#961 H-08, PR
  #963): the start path re-checks the OPEN gates under the Exam row write
  lock before creating the attempt, and the admin transition executor runs
  READ COMMITTED so the unresolved-attempt guard observes attempts
  committed while it waited; both non-serializable schedules are pinned
  closed by deterministic real-PostgreSQL concurrency tests
  (`startCloseConcurrency.test.ts`, 10 scenarios).
- Stale-response and stale-commit ownership across the admin and candidate
  front-end (PRs #955/#957/#959/#965): QuestionPage search (#953),
  RecoveryQueuePage filters (#956), ScoreListPage (#958),
  ExamMonitoringPage timeline/attempt polling (#961 H-02),
  PermissionRegistryPage authority (#961 H-03), StartExamPage single-flight
  entry with route-identity guards (#961 H-07).
- Deadline auto-submit authority (#961 R-02, PR #967): expiry is judged on
  the un-rounded server-adjusted time, the deadline episode submits only
  after a server-side frozen-snapshot verification, and deferral emits
  `deadline_auto_submit_deferred` (`server_deadline_not_reached` /
  `server_state_unavailable`) through the existing `exam_telemetry`
  channel; a manual submit owning the seam releases the episode instead of
  racing it.
- The real-PG 40P01 deadlock coverage fixture is victim-agnostic (#960, PR
  #962).
- The A12(c) Back-debounce and hook external-reset tests are deterministic
  and mutation-verified (#953 test defects, PR #954).

## Known limitations

- **`timed_sync` B2 activation is not in this release.** The B1 kernel is
  implemented but the activation surface remains an explicit future Owner
  decision (#961 scoped it out of the remediation round; the audit records
  `IMPLEMENTED_NOT_ACTIVATED`).
- **The audit's P3 dispositions are recorded, not fixed.** H-09
  (interruption-outcome ordering-key mixture), H-10 (`occurredAt` claim
  annotation required before rendering incidents), H-11 (`bounded_grace`
  formal-model owner + defensive-depth validator) and H-12 (flake-ledger
  items) carry KEEP/DEFER dispositions in the audit issue; none of them is
  a product correctness defect fixed here.
- **Not all H-05 contract-drift targets were rewritten in this release.**
  The exam-runtime / ADR-006 / state-and-authority surfaces were aligned;
  the exam-policy-authority §3/§4 item, the phase-roadmap ↔
  implementation-status item and the ADR-008 evidence-reference item were
  not modified in this range and remain as recorded in the audit snapshot.
- **The audit is a point-in-time adjudication.** The report is a historical
  snapshot at `77f86a30`; each fix carries its own baseline-RED evidence
  against the evolving master, and the audit's "VERIFIED" claims are scoped
  to the scheduling spaces its evidence actually covered.

## Upgrade notes

- **Read §2 of
  [`docs/deployment/upgrade-and-uninstall.md`](../deployment/upgrade-and-uninstall.md)
  first.** The upgrade is the existing paired-image procedure: deploy
  `ghcr.io/jnhu76/exam:v0.0.14` **and** `ghcr.io/jnhu76/exam-web:v0.0.14`
  together (`init-production-env` rewrites `EXAM_IMAGE`/`EXAM_WEB_IMAGE`
  from `.release-version`; no `latest` tag is published). Take the
  mandatory pre-upgrade backup (runbook §15) — it is also the rollback
  material (§2.5).
- **No database migration.** The schema is unchanged from v0.0.13; the
  entrypoint's migration step is a no-op on an up-to-date deployment.
- **No environment or configuration change is required.**
- **Behavioral notes.**
  - Starting an attempt on a closed/cancelled exam now fails
    deterministically at the start gate instead of creating an attempt that
    immediately freezes with a past-time `submittedAt`; candidates hitting
    the race window see the start rejection instead of a frozen attempt.
  - Scanner-terminalized attempts record `submittedAt` at the canonical
    effective deadline (previously the scan tick). Consumers comparing
    `submittedAt` across terminalization paths now see one consistent
    semantics; ordering keys and exports need no change.
  - Deadline auto-submit may defer (with `deadline_auto_submit_deferred`
    client telemetry) until the server confirms the frozen state; the
    server deadline scanner remains the authoritative freezing path, so a
    candidate whose client clock is wrong loses nothing.
  - The admin transition executor runs READ COMMITTED (previously
    REPEATABLE READ) — internal transaction-semantics change, no operator
    action.
- **Rollback (§2.5).** No migrations are involved: rollback = redeploy the
  previous image pair (plus the standard pre-upgrade backup discipline).
  Beware the canonical-pin auto-revert on the next `init-production-env`
  run — pin by digest or edit after (§2.5).
- **Version skipping** stays supported by the migration journal replaying
  any backlog in order.
