# Exam v0.0.8

## Why this release exists

`v0.0.8` closes three campaigns that `v0.0.7` left open, and ships the
candidate-facing rich-editor UX they were building toward.

The first theme is the **Rich subjective-answer trust chain** (#669). The
campaign moved through frozen semantic contracts (Phase B), canonical
closure at the durable acceptance boundary (D1), fail-closed persisted-read
adoption (D3), compact append-only replay receipts backed by a new
migration (D2), export trust (D4), render trust for untrusted static
prompts (D5), publish-boundary validation (D5.1), durable Rich string
closure (F), and permanent regression ownership (G) — and ends with the
candidate editor itself (Phase U): a governed toolbar, a MathLive formula
surface with expert LaTeX source and live KaTeX preview, and explicit
keyboard contracts.

The second theme is **configuration authority repair** (#733). Independent
audits (#728–#732) mapped the real configuration authority graph; the
repairs converge every guard on its single authority (runtime mode,
JWT secret, test-database isolation, seed dotenv admission, shell
test-target resolution) and enforce a root-only `.env`-file source policy
(#741) as a `pnpm verify:static` gate. The same cycle caught and fixed the
one production-facing casualty: the missing root `envFilePolicy.ts` in the
Docker builder COPY (#747) that broke production image builds.

The third theme is **test-evidence integrity** (#706–#722): a
repository-wide owner-layer suite reduction that deletes semantically
dominated tests, deterministic real-PostgreSQL proofs replacing
pseudo-concurrent claims, and process-test hermeticity (explicit profiles,
port ownership bound to the spawned child, a database-isolation lane
contract). The suite gets smaller while owning more of the real fault
models.

The fourth theme is **developer experience** (#689): direct cross-package
Vitest and typecheck now resolve `@exam/domain` from source, so editing
domain code no longer tests stale `dist` output unless a production path
depends on it.

With this release the post-#550 roadmap umbrella (#584) and its two
performance decision gates (#586, #587) are closed; the Rich campaign
umbrella (#669) and the configuration-authority umbrella (#733) are closed
with it.

This remains a **pre-1.0** release.

## Problems solved

- **Untrusted Rich content could reach durable storage, export, render, or
  publish paths on trust that the writer never earned.** The D-phase PRs
  close each seam: canonical closure with structural preflight at the
  serialization gate (#687), typed persisted-answer read classification
  with fail-closed adoption (#690), export trust boundaries for Rich
  answers (#692), fail-closed render trust for untrusted static Rich
  prompts with KaTeX safety evidence (#693), and Rich validation before
  publish projection (#694). Phase F narrows the Rich string domain to
  durable representability (#696), and Phase G consolidates permanent
  regression ownership (#703).
- **Block math could be silently lost on save** — the editor rendered a
  document that differed from the persisted one (#676, fixed in #680 by
  settling the cursor so visible block math survives canonical
  round-trips). The remaining math-selection and table-fidelity gaps are
  closed in #681; the first keystroke after caret relocation into a
  trailing-table region is no longer silently lost (#701, fixed in #702).
- **Answer replay state was expensive and fragile**: every accepted save
  rewrote the whole `exam_attempts.answers` JSONB with a full payload copy
  per accepted `clientSeq`. Phase D2 (#691) moves replay state into the
  append-only `exam_answer_save_receipts` table (migration 0044, with a
  full in-transaction legacy backfill), adds sha256 identity digests for
  new receipts, and restores the take-snapshot `clientSeq` from replay
  receipts. The frozen guarantee holds: no previously accepted replay key
  becomes unknown.
- **The candidate editor had no governed surface.** Phase U (#700) ships
  the frozen interaction contract: a governed 11-command toolbar (canonical
  registry, roving tabindex, narrow-viewport overflow menu, no
  heading/blockquote/link/image/HR anywhere), a formula surface (MathLive
  lazy chunk + expert LaTeX source + live KaTeX preview, 行内/独立显示
  modes, list/table write-side clamps, malformed-LaTeX warning with
  preserve-on-save, re-edit with stale-position and latex-identity guards,
  no-op confirm = zero save requests), and keyboard contracts. It also
  absorbs the lock-presentation fix (#674): the take-page overlay now
  distinguishes disrupted connectivity from deadline lock instead of
  claiming an auto-submit that is not happening, and failed saves retry.
- **Configuration authority had drifted into forks and raw reads.** The
  audit wave (#728–#732, AUDIT_ONLY) established the observed authority
  graph; the repair wave converges: `TEST_DB_ISOLATION` has one authority
  (#735), implicit JWT configuration authority is removed (#736), runtime
  mode guards all route through `parseAppMode` (#738), the seed dotenv
  admission fork is removed (#740), and shell test-schema tooling resolves
  the canonical test target instead of shell-local inference (#742). The
  policy itself is now executable: every physical `.env`-style source must
  live at the repository root, enforced by a new `lint:env-surface` gate
  (#743), and the authority DAG, precedence, and consumers are documented
  (#745).
- **Production image builds broke** when the root `envFilePolicy.ts` (a
  #743 artifact imported by the web vite config) was missing from the
  builder COPY (#747). The fix copies it into the production builder
  (#746, re-landed as #748 with identical content).
- **The test suite owned less than it claimed.** The owner-layer reduction
  campaign (#706–#717) removed semantically dominated tests across web,
  API, domain, contracts, authorization, engine, and database suites while
  keeping every real fault model owned — adding back the rows that were
  sole killers and restoring stronger owners where removal would have
  orphaned a contract. PostgreSQL proof integrity got deterministic
  owners, honest schedule claims, and discriminating oracles (#718, #721),
  then the method went repository-wide (#722): the full forbidden-
  transition space of all three lifecycle tables is owned, concurrency
  claims match established schedules, and the 40P01 retry owner is
  causally deterministic (#727). E2E slimmed to material browser
  boundaries with semantic names (#705) and CI shards dropped from 4 to 2.
- **Process tests were not hermetic**: implicit profiles leaked host
  state, `grabFreePort` had a TOCTOU with foreign health-probe
  attribution (#724, fixed in #725), and suites could resolve foreign
  databases. Process suites now run explicit, hermetic profiles (#734)
  gated to the worker-database isolation lane (#723), documented in
  testing.md §5.2.
- **Direct cross-package tests measured stale artifacts.** After editing
  `packages/domain/src`, direct Vitest in `@exam/contracts`/`@exam/api`
  resolved the built `dist`, so green tests could mean old behavior
  (#689). Test-only source aliases (`vitest.sourceAliases.ts`) and
  typecheck path maps (`tsconfig.typecheck.json`) now resolve the domain
  package-root import to source in direct runs (#746); production Node and
  package entries still resolve to `dist`, and the workflow is documented
  in CONTRIBUTING.md.

`master` (`774e74ef45f78d27b1e01891e0bc9ad85580b203`). The exact range

the `sha-*` alias (deliberately no `latest`), creates or verifies the
immutable annotated `v0.0.8` tag at that exact commit, and creates the
GitHub Release from this file. Publication is complete only after the
workflow succeeds and the tag target, the Release, and the image digests

## Known limitations

- **Pre-1.0 baseline.** This release closes the #669, #733, #706–#722, and
  #584 campaigns; it is not a claim that the generic-product roadmap is
  complete.
- **LAN HTTP requires an isolated or appropriately trusted network**;
  HTTPS remains the recommended transport where certificates are
  available, activated via a runtime-mounted nginx override (no ACME
  automation is bundled).
- **No CDN, object storage, load balancer, or horizontal-scaling
  mechanism.** Single-instance operation; external PostgreSQL is still not
  a supported operator path.
- **Candidate submit serialization / Exam reader lock mode remains a
  recorded deferred follow-up (#668)**, intentionally outside this
  release.
- **Backfilled replay receipts keep legacy payloads** in
  `legacy_answer` for rows accepted before this release (bounded
  compatibility source, never grows post-deployment); identity for those
  rows is derived at read time with the same JS authority.

## Upgrade notes

`v0.0.7 → v0.0.8` adds **one PostgreSQL migration** (0044, the
`exam_answer_save_receipts` table) and does not change the PostgreSQL major
version (still `postgres:18.4-bookworm`), so no dump/restore cycle is
required beyond the mandatory pre-upgrade backup.

Operational notes:

- **Migration 0044 runs automatically** on app-container start
  (`docker-entrypoint.sh` → migrate → server). It is additive except for
  the one-time in-transaction strip of `clientSeq`/`clientSeqHistory`
  from `exam_attempts.answers`, after every legacy receipt row has been
  copied into the new table. A corrupt row carrying the same replay key
  twice fails the migration loudly rather than silently picking a winner.
- **No operator environment changes.** The root-only env-file policy
  (#743) constrains `.env`-style files inside a repository checkout
  (development/build time). The deployed runtime contract
  (`.env.production` consumed by `docker compose --env-file`) is
  unchanged.
- **No mandatory intermediate version**; migrations are
  forward-append-only and the journal applies any backlog in order.
- v0.0.7's one-time orphan-nginx note does not apply to this upgrade
  (no service identity changed since).
