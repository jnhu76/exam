# Exam v0.0.16

## Why this release exists

`v0.0.16` is a correctness, security and observability release cut from
master `081f179e`. Its substance is three campaigns:

1. **The observability plan was re-decided and re-landed natively.** The
   OpenTelemetry implementation waves that landed on master immediately
   after v0.0.15 (PRs [#973](https://github.com/jnhu76/exam/pull/973)–
   [#977](https://github.com/jnhu76/exam/pull/977),
   [#979](https://github.com/jnhu76/exam/pull/979),
   [#980](https://github.com/jnhu76/exam/pull/980),
   [#994](https://github.com/jnhu76/exam/pull/994)) were fully reverted
   by [PR #997](https://github.com/jnhu76/exam/pull/997), restoring the
   v0.0.15 product baseline: ADR-028 is **rejected** and ADR-029 (native
   observability) is adopted
   ([#964](https://github.com/jnhu76/exam/issues/964) closed as
   superseded). The capability then landed as Native Observability V1
   ([#999](https://github.com/jnhu76/exam/issues/999) audit,
   [#1000](https://github.com/jnhu76/exam/issues/1000) umbrella,
   [#1001](https://github.com/jnhu76/exam/issues/1001) modular native
   signal contracts): log-redaction security fixes, email worker
   error-disclosure prevention, and operation-outcome diagnostics for
   submits, admin commands and the deadline scanner.
2. **The full-repository TypeScript code-quality audit
   ([#1038](https://github.com/jnhu76/exam/issues/1038): P0=0, P1=5,
   P2=73, P3=94) drove a risk-first remediation
   ([#1047](https://github.com/jnhu76/exam/issues/1047), disposition
   [#1050](https://github.com/jnhu76/exam/issues/1050))** that closed
   all five P1 findings and the confirmed P2 batch: exam-authoring
   snapshot integrity, grading snapshot freshness, PATCH
   authority/audit integrity, publish transaction consistency,
   deadline-scanner lock stalls, the candidate identity invariant (with
   this release's single database migration), cross-organization read
   isolation, and the machine architecture-gate hardening set.
3. **Runtime and supply-chain hardening:** the Node.js 24.22.3 security
   baseline, glibc container-runtime standardization, pnpm fail-closed
   on stale dependencies, Node 26 test-host compatibility, and the
   conventional-commit policy with its CI gate.

The release contains **one database migration**
(`0047_candidate_fields_org_identity_uidx`), **wire-contract additions**
in the system diagnostics schema (the object is
`additionalProperties: false` — see Upgrade notes), and dev-only
dependency additions (`@commitlint/lint`, `@commitlint/load`). No new
deployment environment variable is introduced.

## Problems solved

1. **Pino error logs could leak data-derived SQL and bound parameters
   ([#998](https://github.com/jnhu76/exam/issues/998),
   [PR #1014](https://github.com/jnhu76/exam/pull/1014)).** Error
   payload flattening could carry data-derived SQL text and bind values
   into log lines; non-Error throwables leaked marker fields, and
   prototype-chain label keys could inject fields. Data-derived
   payloads are redacted, non-Error markers are classified, and label
   keys are own-key allowlisted.
2. **Raw email worker errors reached logs, heartbeat storage and
   diagnostics ([#1012](https://github.com/jnhu76/exam/issues/1012),
   [PR #1016](https://github.com/jnhu76/exam/pull/1016)).** Worker
   failures disclosed raw error payloads across hosts and projections;
   only safe nested error classes survive classification.
3. **Operators could not see why submits, admin commands or scanner
   ticks settled the way they did
   ([#1007](https://github.com/jnhu76/exam/issues/1007)/
   [#1008](https://github.com/jnhu76/exam/issues/1008)/
   [#1009](https://github.com/jnhu76/exam/issues/1009), PRs
   [#1026](https://github.com/jnhu76/exam/pull/1026)/
   [#1027](https://github.com/jnhu76/exam/pull/1027)/
   [#1028](https://github.com/jnhu76/exam/pull/1028)/
   [#1029](https://github.com/jnhu76/exam/pull/1029)/
   [#1030](https://github.com/jnhu76/exam/pull/1030)).**
   Commit-authoritative submit/grade outcome events, admin command
   outcome events with rejection correlation, and deadline-scanner tick
   settlement causality are emitted and documented; DB retry warns are
   correlated with request identity
   ([#1006](https://github.com/jnhu76/exam/issues/1006), PRs
   [#1020](https://github.com/jnhu76/exam/pull/1020)/#1028);
   diagnostics expose heartbeat incident counters
   ([#1004](https://github.com/jnhu76/exam/issues/1004),
   [PR #1019](https://github.com/jnhu76/exam/pull/1019)), classified
   `pingDb` failures across health/diagnostics/ready and the
   due-pending email age in seconds with exact null semantics
   ([#1002](https://github.com/jnhu76/exam/issues/1002)/
   [#1003](https://github.com/jnhu76/exam/issues/1003), PR #1029). The
   V1 closeout
   ([PR #1031](https://github.com/jnhu76/exam/pull/1031)) records the
   remaining contract semantics and the E11 dead-letter decision.
4. **Duplicate `questionIds` could enter a publish freeze snapshot
   ([#1039](https://github.com/jnhu76/exam/issues/1039),
   [PR #1043](https://github.com/jnhu76/exam/pull/1043)).** A repeated
   id would freeze a repeated snapshot item and collide with the
   `attempt_grading_entries` uniqueness at submit time. The request
   schema rejects duplicates, and the canonical exam-policy validator
   re-checks the invariant on persisted/merged policy.
5. **Terminal grading could commit against a stale Exam snapshot
   ([#1041](https://github.com/jnhu76/exam/issues/1041),
   [PR #1046](https://github.com/jnhu76/exam/pull/1046)).** Concurrent
   `extendExam` could permanently write Enrollment `completed` against
   outdated authority; terminal grading now reads the Exam authority
   with FOR SHARE inside the grading transaction.
6. **PATCH authority and audit facts were computed outside their locks
   ([#1042](https://github.com/jnhu76/exam/issues/1042)/
   [#1040](https://github.com/jnhu76/exam/issues/1040), PRs
   [#1044](https://github.com/jnhu76/exam/pull/1044)/
   [#1045](https://github.com/jnhu76/exam/pull/1045)).** User change
   facts are computed inside the authority lock (audit and revocation
   no longer act on a stale snapshot), and draft policy fields
   (`resultPublicationMode`, control flags) are presence-based instead
   of implicitly overwriting whole columns.
7. **Publish decided on pre-read state outside the exam row lock
   ([#1065](https://github.com/jnhu76/exam/issues/1065),
   [PR #1070](https://github.com/jnhu76/exam/pull/1070)).** The content
   snapshot is resolved under the exam row lock inside the publish
   transaction, closing the transaction-outside pre-read window and the
   misleading 400.
8. **A single held row lock could stall the deadline scanner and every
   later tick ([#1071](https://github.com/jnhu76/exam/issues/1071),
   [PR #1075](https://github.com/jnhu76/exam/pull/1075)); shutdown
   could never settle
   ([#1055](https://github.com/jnhu76/exam/issues/1055),
   [PR #1061](https://github.com/jnhu76/exam/pull/1061)).** Scanner
   transactions bound their lock waits (`lock_timeout`), and
   background-loop `onClose` no longer awaits in-flight ticks
   unboundedly (no more guaranteed exit 137 under the 45s grace).
9. **The candidate identity-field invariant had no database owner
   ([#1066](https://github.com/jnhu76/exam/issues/1066),
   [PR #1069](https://github.com/jnhu76/exam/pull/1069)).** A race
   could silently leave an organization with zero or two unique
   identity fields (provisioning DoS, duplicated identity rows).
   Migration `0047` adds a partial unique index — at most one unique
   identity field per organization — with a fail-closed pre-audit; the
   API guards and the candidate-identity advisory lock shared with
   candidate creation ship in the same release.
10. **Cross-organization join reads missed an organization predicate
    ([#1067](https://github.com/jnhu76/exam/issues/1067),
    [PR #1068](https://github.com/jnhu76/exam/pull/1068)).** An
    anomalous cross-organization user link could leak org-B identity
    projections into org-A read models via JOIN; queue list/count and
    related reads are scoped to the caller organization.
11. **A confirmed web P2 batch
    ([#1051](https://github.com/jnhu76/exam/issues/1051)/
    [#1052](https://github.com/jnhu76/exam/issues/1052)/
    [#1054](https://github.com/jnhu76/exam/issues/1054)/
    [#1057](https://github.com/jnhu76/exam/issues/1057), PRs
    [#1063](https://github.com/jnhu76/exam/pull/1063)/
    [#1059](https://github.com/jnhu76/exam/pull/1059)/
    [#1060](https://github.com/jnhu76/exam/pull/1060)/
    [#1058](https://github.com/jnhu76/exam/pull/1058), plus
    [#1034](https://github.com/jnhu76/exam/pull/1034)).** Deadline
    re-read no longer rolls the answer editor back and re-POSTs old
    values; proctor/attempt detail routes re-key their page instance on
    `:id` changes; late session-restore probes are superseded after
    login instead of bouncing the user back to the login page; proctor
    timeline metadata is projected through an allowlist of own keys
    (the prototype-chain index 500 is fixed); operations overview
    polling is isolated per source.
12. **Published exam PATCH could persist a never-open schedule window
    ([#1053](https://github.com/jnhu76/exam/issues/1053),
    [PR #1064](https://github.com/jnhu76/exam/pull/1064)).** Merged
    published schedules are validated by the canonical window rules
    (`openAt < closeAt`) before persistence.
13. **The machine architecture gates could be escaped by syntax
    variants ([#1072](https://github.com/jnhu76/exam/issues/1072)/
    [#1074](https://github.com/jnhu76/exam/issues/1074), PRs
    [#1078](https://github.com/jnhu76/exam/pull/1078)/
    [#1076](https://github.com/jnhu76/exam/pull/1076)), and API test
    sources sat outside the typecheck gate
    ([#1073](https://github.com/jnhu76/exam/issues/1073),
    [PR #1077](https://github.com/jnhu76/exam/pull/1077)).** The route
    DB ban moved to a policy table closing 12 classes of syntax escape;
    dotenv admission holes (dynamic import, subpath) are closed with
    counterfactual kill-cases; `apps/api` test sources and the
    root-level vitest files are inside the typecheck fileset.
14. **Failed-login E2E diagnostics could echo credentials
    ([#1048](https://github.com/jnhu76/exam/issues/1048),
    [PR #1049](https://github.com/jnhu76/exam/pull/1049))** — redacted;
    the rejected-cancel zero-event audit read gained its success
    precondition guard (R-TST-7,
    [PR #1062](https://github.com/jnhu76/exam/pull/1062)).

## Notable changes

### Added

- System diagnostics expose the heartbeat scanner's cumulative
  incident-reconciliation counters (process-local, documented
  aggregation semantics) and `oldestDuePendingAgeSeconds` with exact
  null semantics (#1003/#1004, PRs #1029/#1019); the legacy
  `oldestPendingAge` field is deprecated behind a compatibility window.
- Commit-authoritative submit/grade outcome events, admin command
  outcome events with rejection correlation, and deadline-scanner tick
  settlement diagnostics (#1007/#1008/#1009, PRs
  #1026/#1027/#1029/#1030), documented in
  `docs/contracts/observability.md`.
- Database migration `0047_candidate_fields_org_identity_uidx`: a
  partial unique index enforcing at most one unique candidate identity
  field per organization, with a fail-closed pre-audit that aborts
  before any DDL when an organization already carries duplicates
  (#1066, PR #1069).

### Changed

- ADR-028 (OpenTelemetry migration) is rejected; ADR-029 (native
  observability) is adopted (#964 superseded; PR #997 restored the
  v0.0.15 baseline before the native V1 landed).
- Conventional commit messages are enforced by policy and a CI gate on
  all pull requests (PR #995).
- Container runtimes are standardized on glibc; the web healthcheck
  switched to curl for the trixie edge image; the Node.js base image
  moved 24.22.1 → 24.22.3 (PR #1018).
- pnpm fails closed on stale dependencies before run/exec, and deploy
  installs full workspace manifests before the frozen install
  (PR #1033).
- The `CANDIDATE_FIELD_IN_USE` message now states the actual rule:
  a field in use by candidates cannot be removed as the unique
  identity field (PR #1069).

### Fixed

- Pino error logs no longer leak data-derived SQL/bound parameters,
  non-Error marker fields, or prototype-chain label keys (#998,
  PR #1014).
- Email worker raw errors no longer reach logs, heartbeat storage or
  diagnostics (#1012, PR #1016).

## Upgrade notes

- **Read §2 of
  [`docs/deployment/upgrade-and-uninstall.md`](../deployment/upgrade-and-uninstall.md)
  first.** The upgrade is the existing paired-image procedure: deploy
  `ghcr.io/jnhu76/exam:v0.0.16` **and**
  `ghcr.io/jnhu76/exam-web:v0.0.16` together
  (`init-production-env` rewrites `EXAM_IMAGE`/`EXAM_WEB_IMAGE` from
  `.release-version`; no `latest` tag is published). Take the
  mandatory pre-upgrade backup (runbook §15) — it is also the rollback
  material (§2.5).
- **One database migration: `0047_candidate_fields_org_identity_uidx`.**
  Before deploying, run the mandatory read-only precheck from #1079
  Track C in every persistent target environment:

  ```sql
  SELECT organization_id, COUNT(*) AS unique_field_count
  FROM candidate_fields
  WHERE "unique" IS TRUE
  GROUP BY organization_id
  HAVING COUNT(*) > 1;
  ```

  Zero rows → record environment, time, schema/migration version and
  result, then proceed with the normal backup/upgrade flow. Any row →
  **HOLD DEPLOY**: the migration itself also aborts (fail-closed,
  before any DDL, naming the offending organization ids) with no data
  modified; remediation — which unique identity field each
  organization keeps — is a deliberate operator decision, after which
  the migration re-runs cleanly. The index is the database backstop;
  the API guards and advisory lock ship in the same release, so deploy
  image and migration together as always.
- **Wire additions.** System diagnostics gained
  `oldestDuePendingAgeSeconds`, heartbeat incident counters and
  settlement/outcome events context; `oldestPendingAge` is deprecated
  but identical in value during the window. Strictly-validating
  consumers must refresh their schema copy (`apps/api/openapi.json`).
- **No environment or configuration change is required.** No new
  deployment environment variable; runtime dependency set unchanged;
  Node base image moved 24.22.1 → 24.22.3 inside the image.
- **Behavioral notes.**
  - Removing or demoting an organization's unique identity field while
    candidates exist is rejected (fail-closed) instead of silently
    weakening candidate provisioning.
  - Authoring requests repeating a question id are rejected before any
    draft/publish state changes; previously persisted rows are
    re-checked by the canonical validator on merge.
  - Publish now serializes on the exam row lock; concurrent content
    edits during publish resolve deterministically instead of racing a
    pre-read snapshot.
  - The deadline scanner no longer queues indefinitely behind an
    unrelated held row lock; a bounded lock wait surfaces as a
    retryable skip rather than stalling every later tick.
  - Email diagnostics report due-pending age in whole seconds
    (previously an ambiguously unit-ed value); monitoring thresholds
    keyed on the old field should migrate during the compatibility
    window.
- **Rollback (§2.5).** Migration `0047` rollback is
  `DROP INDEX "candidate_fields_org_identity_uidx";` (the index carries
  no data and constrains only future writes). Otherwise rollback =
  redeploy the previous image pair plus the standard backup discipline.
  Beware the canonical-pin auto-revert on the next
  `init-production-env` run — pin by digest or edit after (§2.5).
- **Version skipping** stays supported by the migration journal
  replaying any backlog in order.
