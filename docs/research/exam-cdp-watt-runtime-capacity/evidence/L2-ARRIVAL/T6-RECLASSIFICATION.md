# P3 T6 重新判定（Owner 评审修订，2026-11-20）

## 背景

`l2-analysis.json` 与各 run 的 `driver.json` 保留了 harness 原始 `t6` 字段（P3 多数为 `PASS`），但该字段没有按冻结协议 §8 的**发送滞后 p99 <50ms** 对 P3 平台展宽做终判。报告旧版把 18 个 P3 型 run 写成 `PASS-WITH-PLATFORM-LAG`，总表仍判 T6 通过；这与协议 §8「任一违反 → 该轮作废并判 `LOAD_GENERATOR_BLOCKED`」直接冲突。

合计 **18 个 P3 型 run 未过 T6**：S50/S100/S200 全部（15）+ S20-r4（1）+ 纯登录 P3 两轮（2）。按协议这些轮次作废，不构成严格同刻容量结论；其余 49 个 run 通过 T6。

## 保留的事实

- P3 行的独立成功数（20/20、50/50、100/100、200/200）是**实际发出负载**下可核对的事实。
- P3-S200 的 6.49s 登录 p99 是该平台该次发射形态的观测值，**不是严格同刻时延上界，也不是 SUT 纯时延**；发射展宽与计时起点都会影响结果。
- 没有事前批准的 T6 修订；`PROTOCOL-ADDENDUM` 只降采样，未改 T6。
