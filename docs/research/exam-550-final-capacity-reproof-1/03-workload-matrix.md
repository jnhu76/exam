## Lifecycle phases per run

| phase | driver behavior | measured endpoint(s) |
| --- | --- | --- |
| LOGIN_BURST | all N candidates login simultaneously | `POST /api/auth/login` |
| START_BURST | all N start the exam simultaneously | `POST /api/attempts/:examId/start` |
| STEADY (90 s) | save every ~5 s ± 2; heartbeat every ~15 s ± 5; 2 proctors poll every ~3 s | answer-save, heartbeat, proctor list, proctor events |
| RECONNECT_SILENCE | 15 s: all clients stop (drop to zero traffic) | — |
| RECONNECT_RESTORE | all N restore in one burst: start-restore + take view | start(restore), `GET .../take` |
| RECONNECT_FIRST_SAVE | all N save in one burst (fresh versions) | answer-save |
| SUBMIT_BURST | all N submit simultaneously | `POST /api/attempts/:id/submit` |

Per-request records land in `results/<run_id>/samples.jsonl` (one JSON line per request:
timestamp, phase, endpoint, status, latency_ms, error_class, timeout). Phase boundaries land in
`pool.jsonl` (`source:"phase"`). Nothing in the summary chain bypasses these raw files.

## Oracles (HTTP success is not accepted as correctness)

Every run ends with durable-state oracles read from PostgreSQL (fresh connection, not the API):

| oracle | assertion |
| --- | --- |
| loginSuccess / submitSuccess | == N |
| attemptStatusCounts | every attempt `graded` (via domain submit path) |
| duplicateActiveAttempts / duplicateTerminalTransitions | 0 |
| answersMatchDurable | last-accepted save per candidate readable back from PostgreSQL with the accepted payload (spot-check Q per candidate, not every version) |
| auditIps | distinct source IPs == N + admin — exercised in the topology group (07), not per lifecycle run |
| pass | all of the above |

Additional NON_CANONICAL diagnostics (labeled as such in artifacts, never mixed into the
canonical envelope): limiter budget isolation probe (two IPs, 130-request burst on one, single
request on the other) and the spoof-negative probes (07).

## Admission matrix (#549 contract) — separate runner

`harness/run-admission.ts`, 15 scenarios: N ∈ {20,50,100,130,200} × Δt ∈ {15 s, 90 s,
ceil(N/20)·15 s} (N=200 uses 150 s). Each scenario: fresh DB + fresh API; join burst; durable
anchor read; real sleep to anchor+Δt; resume burst; start burst (fail-closed 409 expected);
write-once poll round; durable oracle `admitted == min(waiting, (⌊Δt/15⌋+1)·20)`.
