## 3. Problem / Gap

- Current behavior: Most 200/201 responses use `genericSuccessSchema` (`{ type: "object" }`). Request body schemas are validated via Zod at runtime but not registered as Fastify `schema.body`. Role requirements are invisible in OpenAPI. `GET /api/health` is missing from spec. Union responses (`SaveAnswer`, `AttemptResult`) have no `oneOf` representation.
- Impact: API consumers cannot generate typed clients; frontend and backend contracts drift; Phase 2 new APIs would compound the problem.
- Discovery source: `03-openapi-contract-audit.md`
- Why this must be fixed now: Blocks all Phase 2 feature work that adds or modifies APIs.

## 5. User Flow Closed

No direct user flow. This job closes the contract-alignment gap that underlies all frontend to backend flows.

## 6. Current Behavior

- OpenAPI generated via `@fastify/swagger` in `apps/api/src/openapi/swagger.ts`.
- 42 endpoints registered; `GET /api/health` inline in `server.ts:54` missing from spec.
- Most responses are generic `{}`.
- Zod schemas used for runtime validation but not registered with Fastify schema metadata.
- No `security` or `x-role` annotations.

## 7. Target Behavior

- All server-registered routes appear in OpenAPI or are explicitly documented as hidden.
- No implemented route uses generic `{}` response schema.
- All request bodies, query params, and path params are documented.
- `SaveAnswer` accepted/rejected union is represented in OpenAPI `oneOf`.
- `AttemptResultResponse` conditional response is documented.
- Protected routes expose role/security metadata.
- Common error responses are standardized and documented.
- OpenAPI structural/snapshot tests pass and prevent regression.
