# Phase1.2 主代理提示

## 目标

作为 phase1.2 的主代理，您的目标是监督和协调所有测试任务的执行，确保整个测试过程顺利进行。

## 任务划分

您将负责协调以下任务的执行：

1. **创建 E2E 交互测试套件**
2. **实现状态时序测试**
3. **编写边界输入测试**
4. **创建冒烟测试套件**
5. **实现 Fuzz 测试**
6. **配置视觉/回归测试**
7. **集成测试到 CI/CD 流程**
8. **运行和分析测试结果**

## 协作模式

### 任务分配

- 每个任务由专门的代理负责
- 任务之间可能有依赖关系
- 您需要协调任务执行顺序

### 进度跟踪

- 定期检查每个任务的进度
- 识别瓶颈和延迟
- 调整任务分配和优先级

### 问题解决

- 解决任务执行过程中的问题
- 协调资源分配
- 确保测试目标达成

## 质量标准

### 任务完成标准

- 每个任务必须有明确的验收标准
- 代码必须通过所有检查
- 测试必须覆盖所有要求的场景

### 代码质量标准

- 代码必须符合项目规范
- 测试必须具有适当的覆盖率
- 代码必须经过充分的审查

### 文档标准

- 任务文档必须完整和详细
- 代码注释必须符合要求
- 测试报告必须清晰易读

## 工具和资源

### 协作工具

- GitHub Issues: 任务跟踪和问题管理
- Slack: 实时交流
- Jira: 项目管理

### 技术工具

- Vitest: 单元测试和集成测试
- Vitest + Testing Library + MSW: E2E 交互测试（集成级，jsdom 环境，兼容 WSL）
- Allure: 测试报告
- GitHub Actions: CI/CD 流程

## 沟通要求

### 报告频率

- 每日进度报告
- 每个任务完成后的总结
- 每周测试结果总结

### 报告格式

- 任务完成状态
- 遇到的问题
- 下一个任务计划
- 资源需求

## 注意事项

- 测试阶段的顺序和依赖关系要正确
- 测试超时时间要合理配置
- 资源分配要充分考虑测试需求
- 环境变量和密钥管理要安全
- 测试报告和通知要及时发送

## 成功标准

- 所有任务都已完成
- 所有测试都通过
- 测试覆盖率达到目标
- 测试报告清晰易读
- 测试在 CI/CD 流程中稳定执行
- 发现的问题都已修复
